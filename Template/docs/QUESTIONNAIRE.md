# QUESTIONNAIRE

## 사용 목적
이 문서는 템플릿을 실제 프로젝트로 부트스트랩할 때 빠뜨리기 쉬운 결정을 빠르게 확정하기 위한 질문지다.

## 질문 운영 원칙
1. 첫 질문은 항상 `무엇을 만들고 싶은가`에서 시작한다.
2. 답변에서 알 수 있는 항목은 먼저 채우고, 이미 알게 된 것을 다시 묻지 않는다.
3. 질문은 최대한 현재 프로젝트 유형에 맞게 줄인다.
4. 모르면 권장 기본안으로 진행한다.
5. 다음 질문은 현재 결정이 필요한 항목만 묻는다.

## 프로젝트 유형별 질문 예시
- 웹 서비스:
  - 주요 사용자, 핵심 화면, 인증/결제/관리자 여부
- API 서비스:
  - 주요 소비자, 인증 방식, 데이터 모델, 외부 연동 여부
- 백오피스:
  - 관리 대상 데이터, 권한 체계, 운영자 기능
- SaaS:
  - 테넌시, 결제, 계정/권한, 관리자/고객 구분
- 멀티 서비스:
  - 서비스 경계, 배포 단위, 공통 인증/데이터 전략

## 회차 운영
1. 기획을 몇 회차 정도로 나눌 것인가?
2. 각 회차 종료 시 어떤 형식으로 요약을 남길 것인가?
3. 구현은 어느 정도 작은 단위로 끊을 것인가?
4. 사용자가 매 회차마다 승인해야 하는 항목은 무엇인가?

## 서비스와 사용자
1. 이 프로젝트의 핵심 사용자 유형은 누구인가?
2. 사용자가 가장 먼저 수행해야 하는 핵심 행동은 무엇인가?
3. 가입, 결제, 관리자 화면, 상담/추천 로직이 필요한가?
4. 개인화 데이터와 민감정보를 다루는가?

## 제품 범위
1. MVP에서 반드시 필요한 화면과 API는 무엇인가?
2. 관리자 기능이 필요한가?
3. 비회원 사용이 가능한가?
4. 외부 연동이 필요한가? 예: 결제, 인증, 메시징, 분석

## 기술 선택
1. 프런트 패키지 매니저는 무엇을 쓸 것인가?
2. Python 실행/패키지 도구는 무엇을 쓸 것인가?
3. 로컬 DB는 Docker로 띄울 것인가?
4. 캐시, 큐, 스케줄러가 필요한가?

## 품질과 검증
1. 테스트 최소 기준은 무엇인가? 예: smoke, unit, integration, e2e
2. 자동 포맷과 자동 수정은 어느 정도까지 허용할 것인가?
3. 장애 시 어떤 로그와 메트릭을 먼저 볼 것인가?
4. 배포 전 필수 검증은 무엇인가?
5. 회차마다 반드시 실행할 최소 검증 명령은 무엇인가?

## 운영과 배포
1. 프런트와 백엔드를 각각 어디에 배포할 것인가?
2. Preview 환경이 필요한가?
3. Production 배포는 자동인가, 승인 후인가?
4. 롤백은 어떤 단위로 할 것인가?

## 협업 규칙
1. 브랜치 이름 규칙은 무엇인가?
2. commit 규칙을 강제할 것인가?
3. PR 템플릿과 리뷰 체크리스트가 필요한가?
4. subagent 역할 분리를 항상 사용할 것인가, 큰 작업에만 사용할 것인가?

## 문서 운영
1. README 외에 어떤 문서가 반드시 유지되어야 하는가?
2. 문서 업데이트를 Definition of Done에 포함할 것인가?
3. 한국어 단일 문서로 갈 것인가, 영어 병기를 할 것인가?
4. 기획 회차 기록과 개발 회차 기록을 어디에 남길 것인가?
