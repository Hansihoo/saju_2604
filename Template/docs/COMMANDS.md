# COMMANDS

## 목적
이 문서는 Codex에 바로 입력할 수 있는 canonical prompt와, 이후 저장소 루트 명령 이름의 기준을 정리한다.

## 먼저 기억할 것
- 아래 명령은 예시일 뿐이다.
- 꼭 `skill`, `bootstrap` 같은 내부 표현을 외울 필요는 없다.
- 자연스럽게 말해도 된다. 예: `이 프로젝트 초기 설정부터 같이 하자`
- 가장 단순하게는 `프로젝트를 시작해보자`라고만 말해도 된다.

## 권장 루트 명령 이름
- `dev`
- `build`
- `test`
- `lint`
- `format`
- `typecheck`
- `logs`
- `ci`
- `db:up`
- `db:down`
- `db:migrate`
- `preview`
- `release:check`

## Codex에 그대로 말할 수 있는 canonical prompt 예시
- `프로젝트를 시작해보자`
- `이 템플릿을 내 프로젝트에 맞게 초기 설정해줘`
- `이번 회차는 기획 1단계만 진행하자`
- `이 기획을 개발 가능한 기능 명세로 정리해줘`
- `이 기능 명세를 기준으로 개발 전달 문서를 만들어줘`
- `이번 회차 범위만 개발하고 검증, 로그 확인까지 해줘`
- `이 문제를 재현하고 수정 후 다시 확인해줘`
- `배포 전에 체크리스트부터 점검해줘`
- `문서와 현재 상태를 맞춰줘`

## 사용 순서 가드레일
- 현재 작업에 필요한 값이 `{{PLACEHOLDER}}`면 `template-bootstrap`부터 사용한다.
- 요구사항이 아직 모호하면 `feature-delivery`보다 `product-planning`을 먼저 사용한다.
- 증상 재현과 원인 분석이 필요하면 `feature-delivery`보다 `maintenance-bugfix`를 먼저 사용한다.
- 배포 대상과 승인 정책이 미정이면 `release-cicd` 전에 `PROJECT_PROFILE`과 `CI_CD`를 먼저 채운다.
- 이미 확정된 내용을 문서에 반영하는 작업만 남았을 때 `docs-sync`를 사용한다.

## 자연스럽게 말하는 예시
- `프로젝트를 시작해보자`
- `이 프로젝트 시작 준비부터 같이 해줘`
- `아직 구현하지 말고 기본 설정부터 정하자`
- `기획 계속 이어서 하자`
- `이제 이 기획을 개발자가 바로 구현할 수 있게 정리해줘`
- `이번엔 이 부분만 개발하고 확인하자`
- `문제가 생겼으니 원인부터 찾자`

## 명시적 skill 호출 예시
- `template-bootstrap skill을 사용해서 PROJECT_PROFILE의 placeholder를 채우기 위한 인터뷰부터 진행해`
- `product-planning skill을 사용해서 이번 회차는 사용자 시나리오만 정리해`
- `product-planning skill을 사용해서 화면 구조와 UX 우선순위만 이번 회차에서 정리해`
- `feature-delivery skill을 사용해서 승인된 요구사항 중 가장 작은 단위만 구현하고 build/test/logs까지 확인해`
- `maintenance-bugfix skill을 사용해서 버그를 재현하고 원인 분석 후 회귀 테스트까지 진행해`
- `release-cicd skill을 사용해서 CI 상태, 배포 설정, 롤백 계획을 점검해`
- `docs-sync skill을 사용해서 AGENTS와 docs 문서를 현재 규칙에 맞게 정리해`

## 내부 표현을 쓰고 싶을 때만 쓰는 예시
- `template-bootstrap skill로 초기 설정부터 진행해`
- `product-planning skill로 기획 2단계를 이어서 진행해`
- `feature-delivery skill로 이번 개발 회차를 진행해`

## 새 프로젝트 시작 시 순서
1. `프로젝트를 시작해보자`
2. `이번 회차는 문제 정의만 하자`
3. `다음 회차에서 사용자 흐름과 화면 구조를 정리하자`
4. `이 기획을 개발 가능한 기능 명세로 정리해줘`
5. `이 기능 명세를 기준으로 개발 전달 문서를 만들어줘`
6. `첫 개발 회차는 범위를 작게 잡고 검증까지 하자`

## 기획 시작 명령 예시
- `{{FEATURE_NAME}}의 문제 정의만 이번 회차에서 정리하자`
- `이전 기획을 이어서 사용자 흐름과 실패 케이스를 정리하자`
- `화면 구성, UX/UI 우선순위, 사용자 스토리만 정리하자`
- `이 기획 내용을 기능 명세와 acceptance criteria 기준으로 개발 전달용으로 정리하자`

## 개발 시작 명령 예시
- `이 기능 명세와 개발 전달 문서를 기준으로 첫 개발 회차를 시작하자`
- `{{FEATURE_NAME}}의 첫 개발 회차를 진행하자. 범위를 작게 잡고 build/test/logs까지 확인해줘`
- `이전 개발 회차 다음 단계만 진행해줘. 문제가 있으면 수정 후 간단히 문서화해줘`

## 유지보수 시작 명령 예시
- `{{ISSUE_NAME}}를 재현하고 수정 후 회귀 확인까지 진행해줘`

## 릴리즈 시작 명령 예시
- `이번 배포의 체크리스트와 위험 요소를 점검해줘`

## 커밋 요청 예시
- `이번 변경에 맞는 한글 커밋 메시지 추천해줘`
- `태그는 [개발] 형식으로 해서 커밋해줘`
- `기획 변경 반영 여부가 드러나게 커밋 메시지 써줘`
- `커밋 메시지는 [문서] 또는 [구조] 중 맞는 태그로 정리해줘`
