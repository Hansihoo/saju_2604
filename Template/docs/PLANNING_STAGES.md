# PLANNING_STAGES

## 목적
기획을 한 번에 끝내지 않고, 사용자와 여러 차례 대화하면서 점진적으로 확정하기 위한 단계 운영 문서다.

## 기본 원칙
- 한 회차에 한 단계만 다루는 것을 기본으로 한다.
- 각 단계는 문서화 후 다음 단계로 넘어간다.
- 미확정 항목은 억지로 메우지 않고 질문으로 남긴다.
- 사용자 가치, 화면 구조, UX, 실패 흐름이 정리되기 전에는 구현으로 넘어가지 않는다.

## 권장 단계
1. 문제 정의
   - 무엇을 만들고 왜 만드는지
   - 핵심 사용자와 핵심 가치
2. 사용 사례
   - 대표 사용자 유형
   - 주요 시나리오
   - 비정상/실패 시나리오
3. 화면 구조
   - 화면 목록
   - 화면 간 이동 흐름
   - 핵심 상태 변화
4. UX/UI 방향
   - 인터랙션 원칙
   - 콘텐츠 우선순위
   - 피해야 할 UX
5. 기능 범위와 정책
   - MVP 범위
   - 비범위
   - 정책/데이터/권한 가정
6. 개발 전달용 정리
   - 사용자 스토리
   - acceptance criteria
   - 개발 순서

## 각 회차의 출력 형식
- 이번 회차 목표
- 이번 회차에서 확정한 것
- 아직 미정인 것
- 다음 회차에서 다룰 것

## 사용자 스토리 작성 기본안
- 형식: `As a {{persona}}, I want {{goal}} so that {{benefit}}`
- 각 스토리에는 acceptance criteria를 붙인다.
- 구현 방법보다 사용자 목적과 성공 조건을 먼저 적는다.

## 다음 단계로 넘어가는 조건
- 핵심 사용자와 목표가 적혀 있다.
- 주요 화면/흐름 또는 기능 경계가 적혀 있다.
- acceptance criteria 초안이 있다.
- 남은 질문이 분리돼 있다.

## 구현으로 넘어가기 전 체크
- 지금 바로 개발할 최소 범위가 정리됐는가
- 테스트 가능한 성공 조건이 있는가
- 화면/UX 관련 미확정이 치명적이지 않은가
- `FEATURE_SPEC`과 `IMPLEMENTATION_HANDOFF`로 넘길 재료가 있는가

## Codex에 말할 수 있는 예시
- `기획 1단계인 문제 정의만 진행하자`
- `이전 기획을 이어서 사용 사례 단계만 정리하자`
- `화면 구조와 UX 우선순위만 이번 회차에서 확정하자`
- `개발 전달용 user story와 acceptance criteria까지 정리하자`
- `이 기획 내용을 개발 가능한 기능 명세로 정리하자`
