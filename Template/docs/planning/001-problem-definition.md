# Problem Definition 001

## 이번 회차 목표
- `suju-insight`의 문제 정의 초안을 작성한다.
- 무엇을 만들고 왜 만드는지, 이번 단계에서 확정 가능한 수준까지만 정리한다.
- 구현 전에 반드시 필요한 질문을 다음 회차 입력으로 분리한다.

## 이번 회차에서 확정한 것
- 프로젝트명 초안은 `suju-insight`다.
- 이 프로젝트는 사주풀이를 제공하는 웹 서비스다.
- 템플릿 기준 기본 스택은 React + Vite, FastAPI, PostgreSQL이다.
- 프런트는 Vercel, 백엔드는 Render를 기본 배포 대상으로 둔다.
- 1인 개발 기준으로 preview는 사용하고 staging은 두지 않는다.
- production 반영은 수동 승인 기반으로 운영한다.

## 문제 정의
- 사용자가 자신의 사주 정보를 바탕으로 해석과 안내를 빠르게 확인할 수 있는 웹 서비스를 만든다.
- 초기 목표는 "사주풀이를 온라인에서 이해하기 쉽게 제공하는 것"이며, 오프라인 상담 대체나 복잡한 전문가용 도구까지 바로 포함하지 않는다.
- 첫 단계에서는 템플릿 저장소를 실제 프로젝트 시작 상태로 좁히고, 이후 기획 회차에서 사용자 흐름과 MVP 범위를 확정한다.

## 왜 지금 이 문제가 중요한가
- 사주 서비스는 콘텐츠 신뢰감, 입력 편의성, 결과 이해 용이성이 핵심인데, 이 기준이 먼저 정리되지 않으면 구현 우선순위가 흔들리기 쉽다.
- 현재는 서비스 방향만 정해졌고, 핵심 사용자와 첫 행동이 미정이라 바로 구현으로 들어가면 화면/API 범위가 불안정해질 가능성이 크다.
- 따라서 이번 회차에서는 제품 아이디어를 "개발 가능한 문제 정의"로 바꾸는 출발점을 만드는 것이 목적이다.

## 가정
- 사용자는 웹에서 자신의 사주 정보를 입력하거나 선택하고, 해석 결과를 읽는 흐름을 기대한다.
- 초기 버전은 모바일 웹에서도 무리 없이 사용할 수 있어야 한다.
- 운영 복잡도를 줄이기 위해 초기에는 최소 기능 집합으로 MVP를 잡는다.

## 비범위
- 이번 회차에서 화면 목록, 세부 UX, API 명세, 데이터 모델은 확정하지 않는다.
- 이번 회차에서 로그인, 결제, 관리자 기능을 도입한다고 가정하지 않는다.
- 이번 회차에서 실제 서비스 코드 구현은 시작하지 않는다.

## 위험과 미확정
- 핵심 사용자 유형이 아직 명확하지 않다.
- 첫 방문 사용자가 가장 먼저 해야 할 핵심 행동이 아직 정해지지 않았다.
- 로그인/비회원 정책, 결제 여부, 관리자 기능 필요 여부가 미정이다.
- 사주 입력 데이터 중 어떤 항목을 저장할지, 민감정보로 어떤 수준까지 다룰지 미정이다.

## 다음 회차에서 물을 질문
- 핵심 사용자는 누구인가
- 첫 방문 사용자가 가장 먼저 해야 하는 행동은 무엇인가
- 비회원 사용만으로 시작할지, 로그인 기능이 필요한지
- 무료 조회만 제공할지, 결제 기능이 필요한지
- 관리자 화면이 필요한지

## 다음 회차 시작점
- `product-planning` 2단계로 넘어가 사용자 유형과 주요 사용 사례를 정리한다.
- 필요하면 그 다음 회차에서 화면 구조와 실패 시나리오를 이어서 정리한다.
