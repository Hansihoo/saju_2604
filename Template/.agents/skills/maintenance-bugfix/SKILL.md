# 목적
문제를 재현하고 원인을 좁힌 뒤, 수정과 회귀 확인까지 안전하게 마무리한다.

## 시작 전 확인
- 버그의 기대 동작과 실제 동작이 분리돼 있는가
- 재현 조건 또는 로그 단서가 있는가
- 최근 변경이나 관련 컴포넌트를 파악했는가
- 이번 회차에서 재현과 수정 중 어디까지 다룰지 범위를 정했는가

## 수행 단계
1. 재현 절차를 적는다.
2. 로그, 코드, 설정, 데이터 중 원인 후보를 좁힌다.
3. 가장 작은 수정으로 문제를 해결한다.
4. 재현 케이스와 인접 흐름을 다시 검증한다.
5. 운영/개발 문서에 재발 방지 정보를 남긴다.
6. 다음 회차에서 추가로 볼 항목이 있으면 남긴다.

## 산출물
- 재현 기록
- 원인 분석
- 수정 내용
- 회귀 확인 결과

## 완료 조건
- 문제 재현 여부와 해결 여부가 확인됐다.
- 관련 회귀 검증이 수행됐다.
- 같은 유형의 이슈를 피하기 위한 문서가 남아 있다.

## 금지사항
- 재현 없이 감으로 수정하지 않는다.
- 로그나 실패 원인을 확인하지 않고 배포 판단을 하지 않는다.
- 증상이 비슷하다는 이유로 무관한 코드까지 크게 바꾸지 않는다.

## 사용자에게 다시 물어야 하는 경우
- 재현 정보가 전혀 없는 경우
- 데이터 복구, 정책 변경, 운영 영향이 큰 경우
- 장애 대응과 기능 변경이 섞여 있는 경우
