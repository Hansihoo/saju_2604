# 목적
문서와 실제 저장소 상태를 맞추고, 사람이 다음 작업을 바로 이해할 수 있게 유지한다.

## 시작 전 확인
- 어떤 문서가 현재 상태와 어긋나는지 파악했는가
- 문서가 설명해야 할 실제 변경 사항을 확인했는가
- 새로운 제품 결정을 문서화하는 작업인지, 기존 상태를 동기화하는 작업인지 구분했는가

## 암묵 호출 신호
- 구현이나 설정은 끝났고 문서만 현재 상태와 어긋난다.
- AGENTS, docs, skill 문구의 중복과 충돌을 정리해야 한다.
- placeholder와 TODO를 최신 상태로 맞춰야 한다.

## 수행 단계
1. 변경된 저장소 구조와 명령을 확인한다.
2. 영향을 받는 문서를 찾는다.
3. 문서 간 중복과 충돌을 줄이면서 갱신한다.
4. placeholder와 TODO를 최신 상태로 유지한다.
5. 사용자가 다음 액션을 알 수 있도록 요약을 남긴다.

## 산출물
- 갱신된 문서
- 남은 placeholder 목록
- 문서상 미확정 항목 목록

## 완료 조건
- 문서가 현재 저장소 상태와 맞는다.
- 다음 작업자가 문서를 보고 시작할 수 있다.
- placeholder와 확정값이 혼동되지 않는다.

## 금지사항
- 문서에 없는 결정을 임의로 추가하지 않는다.
- 구현 검증 없이 완료된 것처럼 문서화하지 않는다.
- 중복 설명을 여러 문서에 흩어놓지 않는다.
- 프로젝트 기본값을 처음 정하는 작업에서 `template-bootstrap` 대신 쓰지 않는다.

## 사용자에게 다시 물어야 하는 경우
- 실제 구조와 문서 중 어느 쪽이 최신인지 불분명한 경우
- 제품 정책 결정이 필요한 변경이 섞여 있는 경우
- placeholder를 확정값으로 바꿔야 하는 경우
