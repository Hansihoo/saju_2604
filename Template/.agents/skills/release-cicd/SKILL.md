# 목적
릴리즈 전 검증과 배포 후 확인 절차를 체계화해, 자동화와 운영 안정성을 함께 관리한다.

## 시작 전 확인
- 배포 대상과 환경 구분이 문서에 있는가
- 이번 릴리즈 범위와 영향도를 알고 있는가
- 롤백 가능 경로가 있는가
- 배포 승인 방식과 미확정 항목이 정리돼 있는가

## 수행 단계
1. CI 필수 검증 항목을 점검한다.
2. preview, staging, production 정책을 확인한다.
3. 배포 전 체크리스트를 수행한다.
4. 롤백 및 모니터링 계획을 점검한다.
5. 배포 후 확인 항목과 후속 대응 계획을 남긴다.

## 산출물
- 릴리즈 체크리스트 결과
- CI/CD 리스크 목록
- 롤백 계획
- 배포 후 확인 항목

## 완료 조건
- 배포 전후 점검 항목이 문서화돼 있다.
- 롤백 경로와 모니터링 포인트가 분명하다.
- 자동화 범위와 수동 승인 지점이 구분돼 있다.

## 금지사항
- 검증 없이 자동 배포를 완료로 간주하지 않는다.
- DB 변경의 되돌림 가능성을 확인 없이 넘기지 않는다.
- 모니터링 계획 없이 릴리즈 승인하지 않는다.
- 배포 구조 자체가 미정인 상태에서 확정된 것처럼 진행하지 않는다.

## 사용자에게 다시 물어야 하는 경우
- production 승인 방식이 미정인 경우
- 백엔드 호스팅과 배포 단위가 불명확한 경우
- 데이터 마이그레이션 위험이 큰 경우
