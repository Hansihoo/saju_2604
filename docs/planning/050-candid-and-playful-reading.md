# 쉽고 재미있되 불리한 내용도 숨기지 않는 풀이

2026-10-09 사용자 요청: “재미있고 쉽게 풀이해야해. 그리고 사주가 나쁘면 나쁘다고 말해야하고”.

## 목표와 범위

작업 유형은 기존 판정의 표현과 발견된 용어 설명 보강이다. 서버의 21개 규칙 문구와 Codex 생성 지시, 추가 정보 문구를 수정한다. 계산·규칙 선택·불확실성 보류·UI 역할 계약은 바꾸지 않는다.

현재 규칙은 분야별 해석 주제와 조건부 부담을 제공한다. 종합 길흉을 판정하는 규칙은 없다. 불리한 조건을 또렷하게 말하는 것과 명식 전체를 흉하다고 새로 판정하는 것을 구별한다. 047의 종합 풀이 복구/조건부 해석 허용은 이번 작업으로 완료하거나 해제하지 않는다.

## 문장 계약

- 결론부터 말하고 낯선 용어는 작은 기본 접힘 풀이 메모로 옮긴다. “이렇게 살펴볼게/장점과 부담을 함께 봐야 해” 같은 진행 설명으로 본문을 채우지 않는다.
- 기존 조건부 부담은 조건 → 불리한 점 순서로 바로 말한다. 모든 부정 문장 앞에 장점을 붙이거나 뒤에 성장 기회·위로를 자동으로 붙이지 않는다.
- 예: 책임 관련 기존 규칙의 부담은 “일만 늘고 대우는 그대로라면, 이 부분은 불리해. 책임을 더 맡는 것과 인정받는 것은 같은 말이 아니야.”이다. 실제 사용자의 직장 상황을 알고 있다는 뜻으로 쓰지 않는다.
- 유머는 뜻을 쉽게 전달하는 짧은 생활 비유로 만든다. 신호당 강제 농담·빈정거림·모욕·재난 예언·사주 전체 낙인은 사용하지 않는다.
- 원진의 감정 긴장, 고진/과숙의 고독·거리 같은 기존 전통 의미는 긍정적인 장점으로 바꾸지 않는다. 신살 하나가 실제 관계 실패나 삶의 길흉을 확정하지 않는다.
- 좋음/불리함의 새 판단은 서버에 검토된 판정이 있을 때만 표현한다. 기존 휴리스틱 점수, 보이는 오행의 수, 신살 이름·개수는 그 판정이 아니다.
- critical 입력에는 잠정 계산 정보와 용어 설명만 제공한다. 말투를 자신 있게 바꿔 해석 보류를 감추지 않는다.

## 버전과 검증

계산 사실·규칙 버전은 유지한다. 판정 문구, 정보 문구, 생성 prompt, 제품 voice 정책을 각각 독립 버전으로 갱신한다. 관련 API 테스트, 전체 API 회귀, fallback-only 사용자 시나리오, 동결된 세 역할 검토, 실제 모바일 결과를 확인한다. 검증용 유료 모델 호출은 하지 않는다.

내용 검토는 솔직함/이해도/재미/개인별 효용을 구별한다. 말투 개선이나 코드 검사 PASS가 개인별 종합 풀이 효용·전문가 검증·예측 정확도의 PASS는 아니다. 이전 효용 FAIL과 음력30일 실패는 보존한다.
