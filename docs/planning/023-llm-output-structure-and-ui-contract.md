# 023. LLM 출력 구조 및 UI 계약

## 목적

사용자에게 보여주는 사주풀이 결과를 긴 자유 서술이 아니라, 프론트엔드가 안정적으로 렌더링할 수 있는 구조화 데이터로 고정한다.

이 단계의 목표는 두 가지다.

1. LLM이 항상 같은 결과 틀로 응답하도록 만든다.
2. 사용자 화면이 그 틀을 그대로 섹션별로 보여주도록 맞춘다.

---

## 사용자 결과 섹션

서비스는 아래 5개 섹션을 사용자에게 보여준다.

1. 사주 핵심 분석
2. 연애운
3. 금전운
4. 직장운
5. 대운(흐름)

---

## 공통 출력 규칙

모든 섹션은 공통적으로 아래 4가지를 포함한다.

- 특징
- 좋은 점
- 나쁜 점 / 주의점
- 조언

추가 규칙:

- `사주 핵심 분석`은 상대적 특징과 전체 요약을 함께 가진다.
- `대운(흐름)`은 현재 흐름과 다음 흐름 2개만 노출한다.
- 결과는 카드형 감성 문장이 아니라 얇은 구분선 중심의 단순한 섹션 UI로 렌더링한다.
- 개발자용 만세력 raw 데이터는 사용자 화면에 노출하지 않는다.

---

## LLM 출력 목표

LLM은 아래 방향으로만 출력한다.

- 계산된 사주 데이터를 바탕으로 한 결과
- 다른 사주와 비교했을 때 상대적으로 무엇이 두드러지는지 설명하는 결과
- 강점과 약점을 함께 보여주는 결과
- 실제 행동 조언이 들어가는 결과
- 프론트엔드가 그대로 렌더링할 수 있는 구조화 JSON

LLM은 아래 방향으로 출력하면 안 된다.

- 좋은 말만 길게 하는 결과
- 모호하고 추상적인 위로 문장
- 개발자용 만세력 raw 데이터 노출
- 한 덩어리 텍스트로 된 자유 서술 결과

---

## 현재 단계의 제한

아직 아래 계산 규칙은 완전히 들어가 있지 않다.

- 사주의 상대적 강도 계산 규칙
- 여러 사주 대비 percentile 비교 규칙
- “왜 특별한가”를 수치로 설명하는 기준선

따라서 현재 단계에서는:

- `상위 n%`, `하위 n%`, `percentile` 같은 표현은 금지한다.
- 상대적 특징은 오행 편차, 내부 등급, 점수, 활성 신살/길성, 대운 흐름 같은 이미 계산된 팩트만 사용한다.

---

## 백엔드 계약

LLM 응답은 아래 구조를 따른다.

- `summary`
- `core_analysis`
- `love`
- `wealth`
- `career`
- `luck_flow`

세부 규칙:

- `summary`: 한 줄 헤드라인, 핵심 테마, confidence
- `core_analysis`: 특징, 상대적 특징, 좋은 점, 주의점, 조언, 전체 요약
- `love/wealth/career`: 특징, 좋은 점, 주의점, 조언
- `luck_flow.current`: 현재 흐름의 특징, 좋은 점, 주의점, 조언
- `luck_flow.next`: 다음 흐름의 특징, 좋은 점, 주의점, 조언
- 모든 블록은 `evidence_ids`를 포함한다.

---

## 현재 단계에서 LLM에 넘기는 추가 만세력 정보

현재 연애운, 직장운, 금전운에 `현재 기준` 해석을 넣기 위해 payload를 아래처럼 확장한다.

- `current_flow`
  - 현재 연도
  - 현재 나이
  - 현재 대운
  - 다음 대운
- `love_facts`
  - 배우자궁 지지
  - 배우자궁 십성
  - 배우자성 개수
  - 활성 도화/홍염 계열 신호
- `career_facts`
  - 월주
  - 월간 십성
  - 관성/인성/식상 개수
  - 문창귀인, 학당, 장성, 천문성 같은 직업 관련 신호
- `wealth_facts`
  - 재성/식상/비겁 개수
  - 공망, 월덕귀인 같은 재물 해석 보조 신호
  - 비어 있는 오행

이 구조를 쓰는 이유는 다음과 같다.

1. 연애운은 배우자궁, 배우자성, 도화류와 현재 대운을 같이 봐야 현재 체감이 자연스럽다.
2. 직장운은 월주와 관성/인성/식상 조합, 직업 관련 신살, 현재 대운을 같이 봐야 일 방식과 환경 설명이 선다.
3. 금전운은 재성, 식상, 비겁, 비어 있는 오행, 현재 대운을 같이 봐야 현재 돈 흐름과 관리 포인트를 설명하기 쉽다.

---

## 언어 출력 규칙

출력 언어는 `profile.locale` 하나만 따른다.

- `ko`
  - 한글만 사용
  - 한문 출력 금지
- `en`
  - 영어만 사용
  - 한국어, 한문 출력 금지

즉, 사용자 화면에서 읽기 어렵게 만드는 혼합 표기는 실패로 간주하고 fallback 또는 재시도를 탄다.

---

## UI 계약

사용자 결과 화면은 아래 원칙을 따른다.

- 상단에는 결과 제목과 보이는 사주 기둥만 표시한다.
- 요약은 짧은 헤드라인과 한 줄 설명만 보여준다.
- 각 섹션은 동일한 라벨 순서를 유지한다.
  - 특징
  - 좋은 점
  - 주의점
  - 조언
- 핵심 분석에는 추가로
  - 상대적 특징
  - 전체 요약
  를 보여준다.
- 대운은 현재 흐름 / 다음 흐름 두 칸으로 나누어 보여준다.
