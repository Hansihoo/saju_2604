# 063. 풀이 결론과 후속 질문 반영

2026-10-10 사용자 요청: “지금까지 내용 반영해줘”. 060의 C01~C06과 062의 실제 실패를 제품 경로에 반영한다.

## 목표·유형·영향

백엔드의 분석 자료와 게시할 결론을 구별하고, 결론의 실제 조건·근거를 보존한다. 기존 월의 관계와 뿌리/지원 판단을 함께 사용하는 제한된 결론 선정 단계를 추가한다. 개별 분석 문단 전체를 자동 게시하는 대신 선정된 결론을 본문에 사용한다. 재성의 위치를 전체 특징 장에서 반복하지 않는다. 기존 사실/판정 자료는 메모와 원본 응답에 보존한다.

질문 답의 쉬운 풀이와 전문 자료에 서로 다른 표시 역할을 부여한다. 풀이 설명은 기본 본문, 전문 자료는 기본 접힘 메모다. 후속 질문은 서버가 답변에서 이미 해결한 의미를 제외해 공급한다. 클라이언트와 검증 캡처가 같은 서버 메뉴를 사용한다.

## 경계와 위험

새 선정 단계는 기존 제한된 명식 관계의 결론 연결이며 전체 강약·격국·용신이나 돈/취업/인연의 사건 판정기가 아니다. 일반 조언이나 분야명 변경으로 종합 판정 공백을 채우지 않는다. 033 계산·critical 전체 보류·시간 미상 차단·대안 명식 독립 파생은 유지한다. knowledge/rules/copy/표시/추천/검증 버전은 역할별로 갱신한다.

현재 질문만 제거하면 답에서 이미 설명한 다른 질문이 남는다. 질문이 요구하는 의미와 실제 답이 제공하는 의미를 별도 메타데이터로 관리한다. 다음 메뉴가 없으면 억지 질문을 만들지 않는다. 공개 질문의 실제 답은 계속 직접 요청할 수 있다. 타이틀·단어 유사도나 클라이언트 추론으로 추천하지 않는다.

## 검증 방법

공통 명식 조건·반대 조건·대안 명식·미상/critical, 서버 추천의 의미 포함관계와 KO/EN을 테스트한다. 읽기/메모 투영과 이전 응답 호환을 확인하고 실제 API 캡처의 메뉴가 서버 응답과 같은지 검사한다. 같은 가상5사례의 새 fallback 캡처를 독립 reader/evidence로 검토한다. 내용 FAIL을 기술 PASS로 상쇄하지 않는다. 관련 API/웹 타입·빌드·보조 검사와 fallback-only 사용자 시나리오를 실행한다. 유료 생성 provider 검증은 하지 않는다.

## 진행

제한된 구현·기술 검사·새 독립 검토를 완료했다. 콘텐츠 상태는 Needs review다. 원본062와063 r0 실패는 보존한다. r0의 일반 선택 답 메모가 없는 비교 자료를 안내하는 오류를 실제 comparisons 조건으로 수정했다. 시간 미상 사례에서 겉글자 원본 십성 분류와 안쪽의 선택 일간 기준 분류를 혼용한 충돌도 발견했다. 원본 계산을 보존하고 겉/안쪽 풀이 관계를 같은 기존 canonical 표로 대조하며 원본 분류 차이를 메모·derivation에 남겼다. primary 계산/날짜 관례/critical 보류는 변경하지 않았다.

검증 rubric.1의 ‘본문에서 확인된 특징’ 표현이060 C05의 본문 신살 소개 강제 금지와 충돌했다. r0을 그대로 완료한 뒤 rubric.2에서 실제 확인된 이름을 개인 질문으로 알리는 형식을 허용하도록 맞췄다. 존재 여부와 새 정보/연결/실제 약속은 계속 검사하며 8개 기준과 내용 FAIL/HOLD를 유지한다. 수정 결과는 새 r1 캡처·독립 job으로 검토했고, 이전 job을 새 기준으로 재판정하지 않았다.

## 남은 내용 문제

결론 객체와 표시 역할을 분리한 것은 구현됐지만, 현재 선정기는 기존 월/지원 문단을 연결하는 제한된 단계다. ‘지탱하는 요소’의 뜻을 독자가 추측하는 문제와 분야별 일반 조언·개수 설명을 개인별 풀이로 대신하는 공백을 해결한 것으로 승인하지 않는다. 전체 명식의 실제 작용과 반대 조건을 종합해 분야별 결론을 만드는 C01→C02 경로는 별도 미완료다. 지원되지 않는 길흉·만남/취업 시기를 추가하거나 검증 기준을 낮추어 이 공백을 채우지 않는다. 시간 입력 부족은 이 판단기 공백과 구별한다.
