# 076. 구체적인 상세 해설과 나누어 보고한 이유

## 사용자 요청과 원인

사용자는 “왜 나눠서 한거야? 이유가 있는것 아니야? 문제가 있으니까 2번 나눠서 말하던지. 그리고 더 자세히 구체적으로 알려줄 수 있도록 해줘. 사주 내용이 너무 짧아”라고 요청했다.

075에서 표시 누락과 실제 풀이 보류를 따로 처리한 이유는 두 원인이 독립이기 때문이다. visible 필터는 다섯 항목 중 세 항목을 숨겼다. 날짜 경계의 critical 처리는 장문 생성 자체를 건너뛰었다. 또한 일반 입력도 선택된 원국/분야 판단 자료가 얕아 길이만 늘리면 분류 뜻과 한계가 반복되는 문제가 있다. 처음부터 이 차이를 설명했어야 하며 제목 복원을 상세 풀이 완료로 보고하지 않는다.

## 목표·유형·경계

기존 계산 사실과 이미 공급된 분류/관계 뜻을 연결하는 백엔드 상세 해설을 보강한다. 현재 명식의 실제 위치·공존 관계·재산/보상과 거래의 구별·일의 결과와 평가의 구별·현재/다음 구간의 뜻과 다른 날짜 기준의 차이를 설명한다. 정상 writer에는 같은 구체적인 자료를 공급하고, 검증된 날짜 기준 쌍은 조건부 계산/뜻 설명만 제공한다. 출생시간 미상/설명되지 않은 critical은 해설을 만들어 채우지 않는다.

이는 최종 강약/용신/격국·재물의 유불리·취업/만남 시기나 full-report critical 보류를 새로 승인하는 작업이 아니다. 기준을 바꾸어 단정하는 대신 무엇이 같고 달라지는지 계산된 자료로 설명한다. 새 상세 해설의 knowledge/selection/copy를 독립 버전으로 관리하고 본문 claim의 fact/rule 연결과 원본을 메모에 보존한다. 모든 분야에 같은 조언/주의/행동 숙제를 붙이지 않는다.

## 검증

동일 입력의 실제 전후 본문을 비교하고 접힌 메모·제목·반복 안내를 분량에서 제외한다. 정상/KO·EN/날짜 경계/시간 미상·반대 조건과 primary 사실 보존, 생성0과 critical 보류, 새 fact 참조를 검사한다. runtime 스킬의 실제 본문/메뉴/선택 답을 동결해 독자·근거 독립 job을 수행한다. 내용 실패는 기술 PASS나 길이 증가로 상쇄하지 않는다. 관련 API/웹 검사와 fallback-only 사용자 시나리오, 실제 화면 확인 뒤 Codex 테스트 환경에 적용한다. 유료 생성 provider를 회귀에 호출하지 않는다.

## 구현

`reading_detail.py`는 기존 원국 profile, 독립 alternate, 선택된 특징과 원본 기간 사실만 사용한다. 각 블록은 실제 fact ID, 해설 규칙, 적용 조건과 잠정 여부를 갖는다. 뿌리와 지원, 금전 분류별 겉/안쪽 위치, 결과와 평가, 호감과 가까운 관계의 부담, 날짜 기준의 공통점/차이, 현재/다음 주제를 풀어 설명한다. 미상·설명되지 않은 critical에는 새 해설을 만들지 않는다. 모든 출처는 접힌 메모에 남긴다.

정상 writer에도 같은 자료를 공급하며 promptv21은 개인 명식의 실제 공통/상이점을 연결하도록 요구한다. 검증된 model 본문에 고정 해설을 중복 첨부하지 않는다. 기존 최소4412자 계약은 유지하며 조건부 fallback에 그 분량을 통과했다고 주장하지 않는다.

초회 독자 검토에서 태극귀인 답의 “좋은 뜻”이 추상적이라는 지적을 받았다. 기존 카탈로그 출처인 [삼명통회 권3의 論太極貴](https://zh.wikisource.org/wiki/三命通會_(四庫全書本)/卷03)의 `始終相保` 범위에서 시작부터 끝맺음까지의 보호라는 전통적 뜻을 명확히 했다. 검출 조건과 큰 복의 추가 조건은 바꾸지 않았으며 실제 완성이나 조력자 출현을 보장하지 않는다.

## 검증과 남은 문제

- 최종 전체 API585건 PASS(221초)다. 초회 전체584 PASS 뒤 공유조건 테스트를 추가했다. r1 전체585의2FAIL은 갱신한 prompt/question copy의 이전 고정 기대값이었고, 동기화 후 전체585를 다시 통과했다. 관련 검사에서 writer의 fact 자료에 기존 reading_plan도 포함됨을 반영했고 원본 실패 로그를 보존했다. 계산 규칙과 provider 계약은 변경하지 않았다.
- 웹 타입/격리 build 및 기존 reading14/progress8 PASS다. 별도 Chromium의4입력×390/320/1280=12조합에서 다섯 항목·본문 동일·메모 기본 접힘/열기·가로넘침0·만세력 열기/닫기를 확인했다. 실제3질문 HTTP200/결정론 답은 독립 검토 답과 같고 메모·복귀도 통과했다. 콘솔오류0, 최종 UI POST3은 질문이며 모델 호출0이다. 최초 마지막 POST 검사에서 프록시 `/api`를 빠뜨린 기대값을 보정했고 실패 로그를 보존했다. IAB 신뢰 오류와 별도 브라우저 PASS를 구별한다.
- 별도 fallback loopback 사용자 시나리오456PASS/3WARN/기존 음력30일FAIL1이다. 보조 서버는 종료했고, 실행 중 Codex를 검증 때문에 fallback으로 바꾸지 않았다.
- 원래와 새 live 응답의 원국·지역보정·달력·natal facts/profile·critical 상태가 같다. 최초 raw 비교의 차이는 같은 UTC 시각의 Z/+00:00 직렬화와 새 캡처 as_of뿐이며, 정규화 후 같음을 별도 기록했다. 원본 비교 실패도 남겼다.
- runtime 스킬에 따라 r0/r1의 본문·접힌 메모·실제 메뉴·선택 답3개를 동결하고 각 회차에 새 독립 reader/evidence를 실행했다. r0 메모 인용1개의 문자 깨짐은 해당 검토자가 같은 원본에서 반환한 정확한 인용으로만 교체했고 거절 원본/교정 receipt를 보존했다. 최종 r1 두 계약은 수정 없이 유효하며, 기술적 접근 차단이 없는 `input_blind_only`다.

최종 판정은 **code PASS / content FAIL**이다. 쉬운 문구와 메뉴 흥미는 PASS, 실제 후속3답은 모두 met이며 태극 답은 r0 partial에서 met으로 개선됐다. 그러나 main은 partial이다. 독자는 돈의 위치가 이 사람의 금전 풀이에서 무엇을 뜻하는지, 현재와 다음 구간이 개인의 조건과 만나 어떤 해석 차이를 만드는지의 결론 부족을 지적했다. 근거 역할은 사실·조건·본문/메모 정합성 PASS다. 분량 증가나 한 역할의 PASS로 독자 FAIL을 상쇄하지 않는다. 전문가·예측 정확도·실사용자 만족 승인은 없다.

Codex API는 기존 Sol6.1/xhigh 설정으로 다시 읽었고 웹은 유지했다. 동일 경계 입력 실제 HTTP2회는 critical의 deterministic/not_called이며 최종 보존 본문은 독립 검토 본문과 같다. 최초 capture 도구의 메타데이터 키 가정 오류를 보정했고 추론은 없었다. 정상 Codex 실제 생성은 사용자가 처음 화면에서 테스트할 수 있으며 이번 회귀에서 새로 호출하지 않았다. 새 local-result는 원본과 별개로 보존했고 열기 요청은 queued다. 원격 반영은 이 완료 범위를 대상으로 하며 상용 배포를 뜻하지 않는다.

상세 설명 보강은 구현했지만 개인별 금전·직업·기간 종합 결론과 전체 강약/격국/용신 판정은 여전히 미구현이다. 진행상태는 Needs review다. 근거 없는 예측을 붙여 통과시키지 않는다. 원본/새 snapshot·독립 jobs/reviews/report·실패/최종 로그·화면은 등록한 `.dev-runtime/reading-depth-20261024-01a16679`에 보존한다. 사용자 테스트 환경과 local-result도 정리하지 않았다.
