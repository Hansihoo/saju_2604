# 계산 설명과 실제 풀이의 구별

2026-10-09: 사용자가 실제 046 결과에 “실질적으로 도움되는 말은 없고 어떻게 보여줄게라는 식의 내용이 다”라고 지적했다. 이 문서는 효용 실패의 원인, 완료한 검증 보정과 실제 풀이 복구에 필요한 일을 구분한다. 쉬운 문구·레이아웃을 다시 바꾸는 작업이 아니다.

## 확인한 문제와 현재 작업 범위

`basic_reading.py`는 모든 입력에서 `vocabulary_only=true`, `interpretation_rules_applied=false`를 공급한다. `PLAIN_TOPICS`는 십성 그룹의 이름을 생활 주제로 번역한다. 따라서 “일·책임·평가 이야기가 겹친다”는 계산값의 분류 설명이고 개인별 직장/보상 결론이 아니다. 044/046은 표시와 사실 설명을 구현했지만 사용자가 원하는 풀이의 효용은 완성하지 못했다.

기존 별도 해석 경로도 주제당 단일 feature/규칙을 고르고 공통 예시·부담·행동을 붙인다. 초기 8fd02a6의 설명 범위는 참고할 수 있으나 당시의 공통 생활 조언과 가산 점수에 의한 유리한 기간을 무검토로 복구하지 않는다.

이번 변경은 독립 검증 계약·제품 피드백·문서·회귀 검사에 한정한다. 계산 정책 033, 기존 해석 카탈로그, critical 전체 보류, 기본 본문/메모 UI, 모델/운영 설정은 유지한다. 방법 설명을 조건부 해석으로 이름만 바꾸지 않는다. 검증 보정의 위험은 구버전 작업 재사용과 사실 질문의 정상 답까지 부당하게 실패시키는 것이므로 둘을 별도 회귀로 확인한다.

## 사용자가 받아야 할 정보

본문의 순서는 **지원된 결론 → 이 사람에게 그렇게 읽힌 이유 → 반대 단서/조건**이다. 행동은 필요할 때만 붙이며 본문의 정보 자리를 대신하지 않는다. 전문 분류·정밀 날짜·계산 방법은 기존 작은 기본 접힘 풀이 메모에 둔다. 중요한 가정/미지원 범위는 밖에 남긴다.

예를 들어 현재 원문 “지금과 올해는 일·책임·평가 이야기가 겹쳐 보여”는 질문에 대한 결론이 아니다. 이를 “올해 승진한다”, “책임이 커지니 연봉도 오른다”로 고쳐 쓰는 것도 근거 없는 확대다. 먼저 역할·평가·보상 중 어느 결론을 어떤 조건에서 허용할지 규칙을 만들어야 한다. “재성이 안쪽에 세 곳 있으니 돈이 늦게 모인다”, “왕지도화가 있으니 인연이 잘 들어온다”도 현재 자료에서 나오지 않는 결론이다.

## 필요한 서버 판정 계약 — 아직 미구현

기존 계산 snapshot → 질문별 사실 추출 → 적용 가능한 복수 규칙/상충 확인 → 결론 → 문장화 → UI 렌더링 순서를 지킨다. LLM은 마지막 문장화에만 참여하며 계산값에서 새 사건 판정을 만들지 않는다.

새 결론은 적어도 `question_id`, `status`(supported/needs_rule_review/blocked_calculation), `claim_scope`, `statement`, `fact_ids`, `rule_refs`, `counter_signals`, `assumption_ids`, `period`를 갖는다. 미지원이면 statement를 만들지 않는다. 명리 출처·학파 차이·적용 조건·예외·기간 의존성을 규칙마다 기록하고, 프로젝트 편집 정책과 구별한다. 사실/규칙/문구/형식/캐시 버전은 독립 관리한다.

수입·승진·만남 발생을 보장하거나 휴리스틱 점수를 사건 확률/유리한 날짜/다른 사람보다 좋은 운으로 바꾸지 않는다. 전문가 미검토 상태는 그대로 유지한다. 새 기간 비교를 공개하기 전에 관련 전문 검토 요구를 충족해야 한다.

### 알려진 날짜 관례 차이의 별도 결정

1988-11-20 23:30 남성 제천 사례는 현행 23시 일자 변경 정책의 庚辰 일주와 0시 변경 관례의 己卯 일주가 달라 `critical`이다. 현재 계약은 모든 카탈로그 규칙을 보류한다. 기본 결과가 계산 가능하다는 이유로 이 보류를 해제하지 않는다. 십성은 일간에 의존하므로 월간/대운/연운 글자가 같아도 해석이 유지된다고 가정할 수 없다.

조건부 풀이를 지원하려면 알려진 날짜 관례 차이만 별도 유형으로 다루고, 선택 명식의 가정·각 후보의 충분한 사실/규칙 결과·결론별 의존성·비교 일치/충돌·보류를 서버에서 구별해야 한다. 시간 미상·자료 누락 등 다른 critical 유형은 계속 보류한다. primary 계산값은 바꾸지 않는다.

추천 후보는 **선택한 계산 관례를 명시한 조건부 해석과 후보 간 차이를 함께 보존하는 별도 계약**이다. 모든 critical 해제나 불확실성 문구만 붙인 단정은 제외한다. 이는 현행 해석 허용 범위를 바꾸므로 적용 전 사용자의 확인이 필요하다. 조건부 명식 계약이 생겨도 미래 사건 시기 규칙이 자동으로 지원되지는 않는다.
