# 026. 장문형 사주풀이 스타일 전환

## 목적

기존 해석 결과는 `결론 / 근거 / 설명` 카드형 구조였다.
이 구조는 짧고 명확하다는 장점이 있었지만, 실제 사용자가 읽는 체감에서는 다음 한계가 컸다.

1. 사주풀이를 읽는 느낌보다 요약 카드를 읽는 느낌이 강했다.
2. 전문적인 해설보다 분석 조각을 나열한 인상이 남았다.
3. `근거`, `설명` 같은 라벨이 화면의 몰입을 끊었다.
4. 긴 문맥 속에서 성향, 흐름, 비교를 풀어내기 어려웠다.

이번 단계에서는 해석 결과를 `장문형 리딩 원고` 스타일로 전환한다.

---

## 새 방향

이제 결과는 다음 원칙으로 만든다.

1. `근거`, `설명` 같은 라벨을 사용자 화면에서 제거한다.
2. 각 섹션은 기사형 본문처럼 길고 자세하게 쓴다.
3. 소제목과 bullet을 섞어서 읽기 쉽게 구성한다.
4. 전문가처럼 먼저 구조를 짚고, 뒤에서 일반인이 이해할 수 있게 풀어쓴다.
5. 강점, 약점, 주의점, 관리 방향을 함께 적는다.

---

## 출력 구조

최상위 섹션은 유지한다.

1. 내 사주의 특징
2. 연애 / 결혼운
3. 재물운
4. 직업운
5. 대운 흐름

하지만 각 섹션 내부 형식은 기존 카드형이 아니라 아래처럼 바뀐다.

- 섹션 제목
- 긴 도입 문단
- `###` 소제목
- `-` bullet 중심 해설
- 마무리 방향 제시

즉, 내부 스키마는 `title + body` 이고, body는 장문형 원고다.

---

## 프롬프트 방향

프롬프트는 아래 성격으로 바뀌었다.

1. 더 이상 `conclusion/evidence/explanation` 문체를 강제하지 않는다.
2. 한국어 사주 칼럼처럼 길고 상세한 해설을 요구한다.
3. markdown 표는 금지하고, 소제목과 bullet 중심으로 정리하게 한다.
4. 결혼 시기 확정, 재회, 운명의 상대 같은 사건성 예언은 금지한다.
5. 세운 데이터가 없으면 세운을 아는 척하지 못하게 한다.

---

## 화면 렌더링 방식

프론트엔드는 더 이상 라벨 카드를 렌더링하지 않는다.

대신:

1. `###` 는 소제목으로 렌더링
2. `-` 는 bullet list로 렌더링
3. 나머지 줄은 일반 문단으로 렌더링

즉, LLM이 만든 장문 본문이 화면에서 실제 읽을 만한 글처럼 보이게 한다.

---

## 검증 기준

validator는 이제 아래를 본다.

1. 섹션 본문 길이가 충분한가
2. `###` 소제목이 있는가
3. `-` bullet이 있는가
4. 금지 표현이 있는가
5. percentile 근거 없이 `상위 10%`, `20%` 같은 수치 비교를 만드는가

---

## 기대 효과

1. 사용자는 더 이상 해석 조각을 읽지 않고, 실제 풀이문을 읽는 느낌을 받게 된다.
2. 말투와 정보 밀도가 예시 스타일에 더 가까워진다.
3. 강점, 약점, 비교, 흐름, 조언을 한 문맥 안에서 자연스럽게 묶을 수 있다.
4. 화면도 카드형에서 본문형으로 바뀌어 몰입감이 더 좋아진다.
