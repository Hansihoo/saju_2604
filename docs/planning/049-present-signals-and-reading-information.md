# 확인된 특징과 충분한 사주 정보

2026-10-09 사용자 요청: 도화처럼 알려진 항목은 있을 때 설명하고, 없으면 말하지 않는다. 현재 정보가 부족하며 Codex6.1 Sol의 사용 범위를 확인하고 충분한 정보를 공급한다.

## 목표와 범위

작업 유형은 서버의 정보 추출/용어 지식·생성 지시·결과 표시 보강이다. 계산 정책033, critical 해석 보류, 조건부 명식 미승인 상태, 미지원 사건 시기는 유지한다. 명식/대운/신살 계산은 만세력 엔진이며 Codex는 이미 계산된 자료의 문장화를 맡는다. 설정 provider와 실제 응답 provider, 모델 호출 생략/실패 fallback을 구별한다.

## 구현 계약

- 독립 `reading_information` 계약으로 명식 구성, 겉/안쪽 관계 글자, 현재/다음 계산 구간과 발견된 신살의 실제 위치를 공급한다. 원본 사실·전통 용어 설명·개인 해석을 혼동하지 않는다.
- 유명 항목의 표시 지식은 독립 카탈로그/버전으로 관리한다. `active`이고 실제 활성 기둥의 match가 있는 항목만 허용한다. 동일 도화/역마 등의 연지·일지 기준은 위치를 합집합으로 묶고 원래 method/key/matches는 보존한다. 도화 위치 태그를 별개 신살로 중복 나열하지 않는다. 왕지·목욕·함지를 같은 도화 판정으로 합치지 않는다.
- 없는 항목·빈 특징 섹션은 자동 표시하지 않는다. 추천 도화 질문도 실제 도화가 잡힌 경우에만 붙인다. 기존 명시적 사실 질문/기본 API는 호환 유지한다.
- 항목은 이름 → 이 명식의 위치 → 전통적으로 사용하는 의미를 읽을 수 있게 작성한다. 실제 매력·학업 성과·귀인의 등장·이직·부상·질병·관계 결과를 확인했다고 쓰지 않는다. 민감한 이름은 이름 자체의 계산 분류만 설명하고 공포 예측을 하지 않는다.
- 본문에서 개인별 구성상의 차이를 설명하고 한자·십성 표·정밀 경계·신살 판정법은 기본 접힘 메모로 보낸다. 카드 제목만 늘리고 모든 단락을 일반 행동 숙제로 채우지 않는다.
- critical 입력에는 해석을 계속 보류하지만 선택한 기준의 잠정 계산 정보와 명칭 설명을 제공한다. 이것을 조건부 개인 해석 허용으로 간주하지 않는다. 시주·대운 비활성 범위는 준수한다.
- 정상 Codex 생성에는 이 정보 목록을 공급한다. 단일 규칙의 해석 방향은 유지하되 승인된 추가 계산 정보/용어 설명을 작성할 수 있게 한다. 모델이 새 사실/종합 사건 판정을 만드는 것은 허용하지 않는다. fallback에서도 정보가 사라지지 않도록 서버가 같은 정보를 표시한다.

## 검증

최종 표시 보정: 발견된 항목을 기존 본문보다 먼저 보여준다. 정재·편재 등 목록에는 쉬운 주제를 함께 붙인다. 원진·귀문관은 위치 합집합뿐 아니라 실제 짝을 표시한다. critical은 분류마다 잠정 명식 조건을 보이고, 시간 미상에서 대운 정보와 질문이 모두 없는 빈 대운 카드는 숨긴다. 역마는 태어난 사주의 이동 관련 보조 표시로 직업 분류에 넣는다. 초기 fallback의 일반 예시/행동 숙제는 생략하고 기존 answer/tradeoff와 원본 report provenance는 보존한다.

발견/미발견, 잘못된 active/count, 중복 기준·위치 태그, 비활성 시주, critical/시간 미상, KO/EN, 질문 추천/기존 질문 호환, 원본 참조와 실제 표시를 검사한다. 관련 API·웹 타입/빌드·fallback-only 사용자 시나리오 및 실제 모바일 결과를 확인한다. 실제 문장/지식 범위는 동결된 세 역할 검토를 사용하며 본문 효용 FAIL을 구조 PASS로 상쇄하지 않는다. 검증용 유료 모델 호출은 하지 않는다. live Codex의 문구 품질·실사용자 흥미·예측 정확도는 별도다.
