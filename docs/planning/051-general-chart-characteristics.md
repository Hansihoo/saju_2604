# 모든 명식에 공통인 장점·부담·풀이 비중

2026-10-09: 사용자는 ‘내 사주 특징에서 안 좋은 부분과 좋은 부분을 캐치하고 그 정도를 설명’하되 특정 출생 사례에 맞추지 말고 모든 사주에 적용하고, 다른 내용은 펼쳐 보도록 요청했다. 개인의 계산 관례를 다시 선택하도록 묻는 흐름은 중단한다.

## 최신 사용자 평가 — 내용 방향 재검토

같은 날 구현 결과를 보고 사용자는 “어떤 운을 타고 났고 어떤 불행을 타고 났다 어떤 흐름이 있다”, “내 성격 테스트 같은 심리 테스트 느낌”이라고 거절했다. 현재 10개 규칙은 십성 그룹의 동시 존재를 현대 환경별 장점/부담과 연결하고, 정도도 편집상 비중으로만 표시한다. 원국의 복/흉이나 원국·대운·세운 상호작용을 종합 판정하지 않는다. 따라서 좁은 핵심 효용 PASS를 사용자가 원하는 운세 풀이의 성공으로 인정하지 않는다.

다음 내용 계약은 **원국의 분야별 유리한 구조/불리한 구조 → 대운·세운이 이를 돕거나 방해하는 차이 → 지원된 결론·정도·반대 단서 → 접힌 전문 근거**다. 기질 설명은 보조로 둔다. 성격 문장을 재물복·배우자복 말투로 치환하거나 지금의 편집 비중을 길흉 강도로 바꾸는 작업은 하지 않는다. 분야별 성립/예외/완화/기간 규칙이 먼저 필요하며 아직 구현되지 않았다.

《子平真詮》의 [成敗救應](https://donglishuzhai.net/chapter/3722.html)은 조합의 성립·손상·보완 조건을, [論行運](https://donglishuzhai.net/chapter/3738.html)은 운의 글자와 원국의 관계를 함께 판단하는 방법을 논한다. 이는 자평 계열의 전통적 해석 구조에 대한 배경이며 현대 사건 예측의 실증이나 이 프로젝트의 규칙 승인이 아니다. 특정 불행이 평생 확정됐다는 결론으로 확대하지 않는다.

이 피드백은 제품 정책 독립 버전 `fortune-reading-direction-2026-10-09.1` / presentation `.2`와 에이전트 계약에 보존했다. 이전 코드/검토 기록은 유지한다. 이번 턴은 문서/방향 보정으로 실제 규칙·응답·화면·provider를 수정하지 않는다.

문서 보정 검증: 제품 JSON 파싱/새 버전·사용자 거절 상태 검사, 기존 web reading helper14, diff check 통과. 계산/응답/런타임 동작을 바꾸지 않아 API·브라우저·fallback 시나리오는 재실행하지 않았으며 기존 결과를 새 성공으로 보고하지 않는다.

## 목표·범위·위험·검증

기존 primary 계산과 기존 full-report 규칙/critical 보류는 유지한다. 새 독립 특징 계약에서 명식의 두 십성 그룹과 위치 조건을 연결한 **프로젝트 조건부 해석**을 제공한다. 본문은 장점과 부담을 각각 선택하며, 같은 근거라고 무조건 양쪽을 채우거나 서로 상쇄하지 않는다. 고전의 격국 성립·신강·용신·실제 재능/피해·사건 예측을 판정하는 기능은 아니다.

정도는 ‘이 프로젝트 풀이에서의 비중’이라는 서열 척도다. 초점 그룹에 관해 (1) 일간 자체를 제외한 겉 천간, (2) 월지 본기, (3) 그 겉 천간과 다른 기둥의 지장간이라는 조건을 별도로 확인한다. 세 조건이면 두드러짐, 두 조건이면 눈에 띔, 나머지 매칭이면 보조 수준이다. 서로 독립된 통계적 증거나 실제 효과의 크기라고 부르지 않는다. 규칙 미매칭/필수 사실 누락에는 등급을 만들지 않는다. 오행 개수·신살 weight/개수·기존 내부 점수는 입력으로 쓰지 않는다.

출처 배경은 《三命通會》卷五의 십성/조합·조건 논의와 《子平真詮》論用神成敗救應의 성립·예외 검토다. 현재 현대 문구/조합 선택/비중 척도는 프로젝트 편집 규칙이며 이 문헌이 그대로 보증한 공식이 아니다. 전문가 검토와 실증 검증은 not_completed다.

## 처리 경계

계산 snapshot → 사실 adapter → 순수 규칙/비중 평가 → 공급된 문장/접힌 메모 → React 표시. 모델 호출이나 재계산 없이 제공한다. 새로운 사실·지식·규칙·비중·문구·형식 버전은 기존 reading plan/information과 독립 관리한다. 정상 입력·남녀·지역·생일 전체에 같은 규칙을 적용하고 특정 생년월일/일주 분기를 넣지 않는다.

현재 조건부 조합 규칙은 10개다. 비중이 큰 항목을 먼저 고르고 동점에는 카탈로그 순서를 유지한다. 방향·초점 그룹이 같은 항목은 하나만, 장점/부담은 각각 최대 두 개만 본문에 선택한다. 비교의 추가/빠짐은 **선택된 항목끼리의 차이**이며 그 명식에 해당 구조가 전혀 없다는 판정이 아니다.

날짜 관례 차이만 확인된 경우 새 특징 범위에서 선택된 primary를 가정하고 조건부 풀이한다. primary 값이나 기존 full-report 보류를 바꾸지 않는다. 후보 명식의 네 기둥을 검증하고 후보 각각의 일간으로 십성·규칙·비중을 다시 산출한다. 본문에 기준에 따른 조건부임을 짧게 표시하고 후보별 같은/추가/빠진 항목과 비중 차이는 풀이 메모에 둔다. 다른 critical, 시간 미상, 불완전 후보, 검증되지 않은 차이가 섞이면 이 예외도 적용하지 않는다.

본문에는 직접 결론·비중·쉽게 읽는 이유·불리해지는/약해지는 조건을 둔다. 전문 이름·정확한 위치·원본 출처·후보 명식·비중 산정 조건은 기본 접힘 메모로 둔다. 다른 날짜 기준을 숨겨 명식이 확정된 것처럼 보이게 하지 않는다. 기존 발견된 신살은 별도 정보로 유지하되 이 척도에 가산하지 않는다.

검증은 순수 규칙의 반대 사례/누락/중복/순서·KO/EN·입력 다양성, 정상/sect만/다른 critical 혼재/시간 미상, 기존 보류와 신규 범위 분리, fallback-only 사용자 시나리오, 실제 모바일 본문·메모 펼침/닫힘을 포함한다. 질문자·답변자·감독관은 새 동결 결과로 독립 검토한다. 코드 PASS와 사용자 효용/전문가 검토를 구별하고 기존 FAIL을 지우지 않는다.
