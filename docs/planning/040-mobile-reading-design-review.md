# 040. 모바일 결과 디자인 검토와 풀이 메모

작성일: 2026-10-07. UI 문구/표시 개정: `reading-memo-2026-10-07.1`.

## 목표와 범위

사용자가 선택한 풀이를 가볍게 읽고, 전문 설명은 필요할 때 확인하고, 마음에 든 문장을 카드로 공유한다. 이번 구현은 기존 전문 노트의 문구와 접힘 표시다. 지수 산식·비교 데이터·API 계약·모델 설정은 변경하지 않았다. 숫자는 [039](039-fortune-index-design.md)의 미구현 설계다.

## 조사와 적용 판단

[GOV.UK Details](https://design-system.service.gov.uk/components/details/)는 일부 사용자만 필요한 정보를 펼침에 넣고 핵심 정보는 숨기지 않도록 안내한다. 탭/아코디언보다 시각적 강조가 낮아 보조 설명 한 덩어리에 적합하다고 설명한다. 여기서는 전문 설명이 해당 역할이며 결과 본문·날짜·출생시간 미상 안내는 바로 표시한다.

[NN/G Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)는 기본 작업과 추가 정보를 단계적으로 제시하는 원칙을 설명한다. 이 원칙을 적용해 본문을 접지 않고 계산 근거의 상세 설명만 뒤로 둔다. 이 자료가 이 제품의 흥미나 공유 증가를 검증한 것은 아니다.

[W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)은 AA 기준으로 24×24 CSS px 또는 정해진 예외를 제시한다. 이 UI는 글씨를 12px로 낮추되 터치 영역 높이는 44px로 잡았다. 44px가 AA의 필수 수치라고 소개하지 않는다. [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)에 따라 작은 회색 글씨에도 읽을 수 있는 대비가 필요하다. 흐린 글씨보다 정보 계층과 간격으로 조용하게 표현한다.

## 구현한 표시

- KO `풀이 메모`, EN `Reading memo`: 본문 아래 작은 회색 글씨와 화살표. 중요성을 과장하는 질문·검증 배지·추가 광고 문구를 붙이지 않는다.
- native `details/summary`, 기본 닫힘, 초점 테두리. 부모의 기존 `trace_id:topicKey` 키가 결과/주제 변경 때 메모를 재생성한다.
- 열면 공급된 명식 사실과 해석 기준만 표시한다. 내부 `analysis_note`/`basis_explanation`와 전문 문체는 유지한다. 정보가 없으면 메모를 만들지 않는 기존 어댑터를 유지한다.
- 문구는 `experienceCopy.ts`, 색/간격은 `experience.css`, 접힘은 `DokkaebiReadingBasis.tsx`, 사실 연결은 `readingBasis.ts`에서 관리한다. 계산/해석 규칙 버전과 UI 문구 개정을 혼동하지 않는다.

## 다음 디자인의 우선순위

다음 항목은 코드와 기존 결과 문서를 바탕으로 한 디자인 제안이다. 새 모바일 결과의 실제 관찰이나 사용자 선호 검증을 완료한 안이 아니다.

| 순서 | 제안 | 이유와 구현 조건 |
| --- | --- | --- |
| 1 | 선택한 주제·실제 날짜 → 가장 중요한 한 줄 → 풀이 본문 → 풀이 메모 | 결과에서 시선이 머물 곳을 한 곳으로 만든다. 강조 한 줄에만 명조를 쓰고 본문은 고딕을 유지한다. 날짜가 공급되지 않은 주제에 임의 날짜를 넣지 않는다. |
| 2 | 결과 카드의 배지·틀·반복 제목을 줄이고 문단 간격을 넓힌다 | 모든 요소를 같은 크기로 강조하면 핵심이 약해진다. 먼저 실제 결과에서 중복을 찾아 제거하고, 본문 역할이나 계산 한계는 삭제하지 않는다. |
| 3 | 캐릭터는 답변 옆 작은 리액션, 공유 카드에서는 큰 표정 | 읽는 화면은 문장이 주인공이고 공유 화면은 캐릭터가 기억을 돕는다. 좋은/나쁜 표정을 계산된 길흉으로 오해시키지 않는다. |
| 4 | 하단 주요 행동은 기존 카드 만들기 하나 | 버튼 경쟁을 줄인다. 주제 이동과 입력 수정은 보조 컨트롤로 유지하고 safe-area와 본문 끝 여백을 확인한다. |
| 5 | 운세 지수 구현 후 큰 정수 + 짧은 정의, 상세는 같은 풀이 메모 | 큰 숫자는 빠르게 훑기 좋지만 정확성을 과장할 수 있다. 검토된 서버 지수·대상 기간·해석 지수 정의가 준비된 뒤 적용한다. 소수점·확률·인구 순위·임의의 좋은 날짜를 넣지 않는다. |

캐릭터와 기존 따뜻한 배경을 유지하고 강조색은 한 계열로 제한하는 방향을 권한다. 새 폰트 라이브러리나 UI 프레임워크보다 현재 문구/스타일/컴포넌트 분리 구조로 먼저 다듬는다. 디자인만으로 사용자가 원하는 미래 정보를 새로 만들 수 없으므로 038의 기간 사실·해석 규칙 보강을 병행해야 한다.

기존 fallback 검증의 음력 1990-02-30 입력 422 FAIL은 해결하지 않았다. 이번 변경에서 전체 API 회귀를 반복하지 않았으며 기존 456 PASS/3 WARN/1 FAIL을 새 검증 결과로 재사용하지 않는다.
