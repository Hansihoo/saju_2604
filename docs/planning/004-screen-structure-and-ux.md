# Screen Structure And UX 004

## 목적
- 확정된 입력 정책과 결과 노출 정책을 바탕으로 MVP 화면 구조와 UX 원칙을 정리한다.
- 다음 단계에서 기능 명세와 API 경계를 구체화할 수 있도록 화면 단위 기준을 만든다.

## MVP 화면 목록
- 랜딩 화면
  - 서비스 설명
  - 개인 해석 시작 CTA
  - 정확한 계산과 설명 가능한 해석 강조
- 입력 화면
  - 양력/음력 토글
  - 생년월일 입력
  - 생시 입력(HH:mm)
  - 성별 선택
  - 지역 검색 입력 + 제안 리스트 선택
  - 출생시간 미상 안내
- 결과 화면
  - 요약 카드
  - 강점/약점
  - 연애운/직업운/금전운
  - 대운 흐름
  - 행동 조언
  - 상세 근거 펼침 섹션
- 오류/제한 상태 UI
  - 지역 선택 실패
  - 시간 보정 실패
  - 출생시간 미상으로 인한 일부 결과 비활성화

## 입력 화면 UX 원칙
- 기본값은 사용자의 입력 부담을 줄이는 방향으로 둔다.
  - 달력 기준 기본값은 양력
  - 지역 기본 경험은 한국 중심
- 정확도에 직접 영향을 주는 값은 자유 입력보다 선택형을 우선한다.
  - 지역은 검색 후 제안 리스트 선택 방식
- 생시를 모르면 비워두게 하지 않고 `00:00`으로 진행하되, 결과 신뢰 범위를 분명히 알린다.

## 결과 화면 UX 원칙
- 첫 화면은 해석을 빠르게 이해하는 요약형 구조로 시작한다.
- 오행, 십성, 대운은 처음부터 전면 노출하지 않고 접힌 상세 영역으로 제공한다.
- 사용자는 필요할 때만 근거를 펼쳐볼 수 있어야 한다.
- 점수와 등급은 내부 계산에 쓰되, 사용자에게는 해석 중심 문장으로 먼저 전달한다.

## 출생시간 미상 처리 UX
- 입력 단계:
  - 사용자가 시간을 모를 경우 기본값 `00:00`으로 진행 가능
  - 이 값이 추정값임을 명확히 안내
- 결과 단계:
  - 시주 기반 정보는 비활성화 또는 제한 표시
  - "출생시간이 정확하지 않아 일부 해석이 제외되었습니다" 같은 안내 문구 제공
- 개발 가드레일:
  - `is_birth_time_estimated=true`일 때 시주 기반 분석을 일반 결과처럼 노출하지 않는다.
  - 시주 기반 점수/등급 가중치가 있다면 제외 또는 별도 처리한다.

## 지역 선택 UX
- 사용자가 지역 입력창에 텍스트를 입력한다.
- 시스템이 연관된 지역 후보를 리스트로 제안한다.
- 사용자가 리스트에서 하나를 선택해야 다음 단계로 진행할 수 있다.
- 선택 결과는 최소한 `country`, `city`, `iana_timezone`으로 정규화한다.

## 상세 근거 UX
- 기본 접힘 상태:
  - 오행
  - 십성
  - 대운
- 펼침 상태:
  - 핵심 계산 결과 요약
  - 해석 이유
  - 사용자에게 보여줄 설명 문장

## 이번 회차 결정
- MVP 화면은 `랜딩 -> 입력 -> 결과`의 단순 구조로 시작한다.
- 지역은 자동완성 검색 후 선택 방식으로 고정한다.
- 오행/십성/대운은 접힌 상세 영역으로 제공한다.
- 출생시간 미상은 허용하되 시주 기반 결과를 제한한다.
