# 062. 임의 출생5개 런타임 검증과 보강

2026-10-10 사용자 요청: “5개의 사주 임의로 만들어서 런타임 검증 및 보강해줘”.

## 목표와 범위

seed 20261010으로 유효한 가상 출생일시5개를 만들고 실제 계산된 사주를 검토한다. 처음3개는 일반 시각, 네 번째는 시간 미상, 다섯 번째는 날짜 변경 경계다. 결과를 미리 계산해 유리한 사례를 고르지 않는다. 개인정보를 재사용하지 않는다.

061의 프로젝트 스킬로 본문·접힌 근거·표시된 모든 질문·선택 답을 같은 회차로 동결한다. 새 독자/근거 에이전트는 자신의 역할job 전체만 읽고 원작성자의 의견이나 다른 검토의 판정을 받지 않는다. 최대2회 보강/재검토하고 원본 실패를 보존한다.

## 변경 원칙과 위험

테스트 입력 주입은 캡처 도구에서만 허용하며 API 계산·provider 설정을 변경하지 않는다. 보강은 기존 판정의 실제 범위를 지키는 결론 선정·문장·질문 연결을 대상으로 한다. 계산033, knowledge/rules/copy의 독립 버전, 시간 미상/critical 보류와 전체 강약·용신·사건 시기 미지원은 유지한다. 자료가 부족한 답을 장문화하거나 근거 없는 새 예측으로 PASS시키지 않는다.

## 검증

관련 API/검증 계약·웹 보조 검사와 fallback-only 사용자 시나리오를 실행한다. 실제 브라우저의 본문/기본 접힘/질문 선택·답변·복귀를 확인하되 연결이 막히면 API와 독립 내용 검토를 계속하고 UI를 HOLD로 남긴다. 최종 판정과 남은 보강 범위는 PROJECT_STATUS/WORK_LOG에 기록한다. 가상 출생 정보와 원본 응답·검토는 등록된 ignored evidence root에 보존한다.

아래 출생정보는 검증용 가상 자료다. 태어난 시간을 모르는 사례의00:00은 실제 시각으로 쓰지 않는다.

| 5 | 1984-05-11 23:45 여 | 제천, 날짜 변경 경계 | 甲子 己巳 丙午 戊子, 원래 critical 전체 보류 유지 |

공유 원인에 다음 보강을 적용했다. 특정 생년월일 분기는 없다.

- 월령·지원·재성·공존 조건을 표현하는 모든 기존 natal 문구를 KO/EN으로 다시 썼다. ‘몫·밑바탕·전체의 무게·돈을 쥐는 것보다’ 같은 추상 비교를 제거하고 무엇을 읽는지, 공존과 실제 결과의 차이를 직접 설명한다. 유리/불리를 문단마다 억지로 맞추지 않는다.
- 적용된 배움/거리 특징의 질문이 본문과 연결되도록 짧은 맥락을 추가했다. 신살별 독립 소개나 전체 풀이 대체는 하지 않는다. 호환 본문과 publication이 같은 내용을 사용한다.
- 태극/배움-거리 질문은 배움의 분야와 시작·마무리 과정, 관계와의 구별을 실제 답에서 설명한다. 도화 질문과 답은 실제 검출 방식과 다른 방식의 차이, 서로 합쳐 강도로 읽으면 안 되는 이유를 함께 제공한다. 미지원 인연·취업 시기를 약속하지 않는다.
- 새 입력 캡처는 birth-only 필드를 검증한다. 실제 API 필드 `is_lunar_leap_month`를 보존하고 오타 필드/계산 사실·중복ID 주입을 거부한다. 기본4사례도 유지한다.

본문의 단어만 고쳐도 전체 판정은 완성되지 않는다. `natal_structure`의 조건별 고정 문단을 하나의 개인별 결론으로 통합하는 과정, 금전의 벌이/축적/손실, 연애/취업과 기간 상호작용의 검토된 판정 규칙은 여전히 없다. 현재 일반 조언·개수·대운 용어만 있는 장은 궁금증 충족으로 통과시키지 않는다.

## 독립 버전과 증거

명리 knowledge/rules와 계산033은 유지했다. natal/distinctive/question copy와 publication은 각각2026-10-10.2다. 마지막 보강에서 category copy는2026-10-10.4, information copy는2026-10-10.2, dokkaebi copy는2026-10-10.1로 갱신했다. 검토 prompt.4/capture.2를 사용하며 rubric.1/계약 runtime-reading-review-v1은 변경하지 않았다. 큰 근거 job은 실제 적용 정책만 투영하고 제외된 비공개 과거 템플릿/원본 hash를 기록한다. main과 공개된 모든 선택 답을 같은 cohort로 나누고 역할별 새 에이전트가 검토한다. 도구 접근의 기술적 차단은 없어 input_blind_only다.

현재 대화 소유 등록 경로 `.dev-runtime/five-chart-runtime-20261010`에 입력, r0/중간r1/최종r1/r2 snapshot, job, 최초 실패와 독립 재검토를 보존한다. 캡처는 실제 fallback ASGI 본문5개와 공개 선택 답3개이며 생성 모델 호출0회다. 전체 source 응답은 문구/버전/시각이 달라지지만8개 응답의 frozen facts, 입력·지역·보정·음양력·명식과 active 규칙 조건/knowledge/rules 버전 및 critical guard는 원본과 일치했다. reading_payload도 명시한 copy metadata와 출력 문장/제목을 제외한 사실/조건은 일치한다.

두 번째이자 마지막 보강은 r1 독립 실패를 대상으로 한다. “마음을 말과 함께 보내는 시간으로 표현”을 “마음을 말로 표현하고 함께 시간을 보내는 일”로 고쳤다. “경쟁·나눔”은 “다른 사람과 경쟁하는 일·역할과 자원을 나누는 일”로 펼쳐 대상을 밝혔다. 근거 검토에서 시간 미상 본문은 보류인데 메모의 일간/표시 설명은 확정형이라는 불일치도 발견했다. 잠정 정보의 각 제목·설명·메모에 선택한 임시 명식의 자료라는 조건을 유지하고 ‘네 사주’라는 확정형 대상을 바꿨다. 전체 종합이나 기간 상호작용의 새 판정으로 확대하지 않았다.

마지막 검토 자료는 두 캡처에 연결된다. 일반1~3과 선택 답3개는 `snapshot-r2-with-scoped-notes.json`, 불확실 입력4~5는 조사 오류 “명식를”을 고친 `snapshot-r2-scoped-final.json`이다. 4~5의 검토 시작 전 새 snapshot-v2/jobs-final-v2를 만들었고 기존 준비 자료도 보존했다. 1~3의6개 응답은 독자·근거 양쪽의 투영된 job case 전체가 최종 캡처와 같음을 assert했다. `r2-capture-equality-receipt.json`과 `review-r2/cohort-final-selection.json`에 출처를 남겼다. 원 검토를 새 hash의 검토로 바꿔 부르지 않으며, raw 응답 시각/trace 차이도 숨기지 않는다. 이전 checkpoint와 실패는 모두 보존한다.

## 회귀와 남은 검증

관련 API/계약/질문 회귀151개 PASS. 이후 캡처 윤달 입력 필드를 수정한 좁은 계약20개도 PASS. 문장 변경 후71개, 잠정 근거 보강 후 information/knowledge/category/basic/question/publication87개 PASS, 마지막 조사 수정 후 information12개 PASS(겹치는 검사 건수를 더하지 않는다). 웹 helper14 PASS. Fallback-only 사용자 시나리오456 PASS/3 WARN/기존 유효 음력30일FAIL1, 생성 모델0. 구 태극 제목/질문 copy버전을 기대한 assertion은 새 질문 계약으로 갱신했다. basic 테스트의 수정 중 들여쓰기 오류를 바로 고친 뒤 재실행했다. 새 잠정 메모 테스트는 허용된 조건부 natal과 전부 보류된 provisional_information을 구별해 검증한다.

현재 브라우저 연결은 `privileged native pipe bridge is not available; browser-client is not trusted` 오류로 실패해 UI HOLD다. 다른 도구로 우회하지 않았고 새 브라우저 통과를 주장하지 않는다. 전문/실증 정확도와 실제 사용자 흥미도 미검증이다.

## 최종 독립 검토 결과

원본r0 → 첫 보강r1 → 마지막 보강r2마다 새 독자·근거 job으로 검토했다. 아래 이해도는 각 사주의 본문 기준이다. 궁금증 충족은 모든 회차의 본문5개에서 FAIL이다.

| --- | --- | --- | --- | --- |
| 1 일반 | FAIL → FAIL → PASS | FAIL / partial | PASS | FAIL |
| 2 일반 | FAIL → FAIL → PASS | FAIL / partial | PASS | FAIL |
| 3 일반 | FAIL → PASS → PASS | FAIL / partial | HOLD / 메뉴 없음 | FAIL |

| 5 날짜 경계 | FAIL → PASS → PASS | FAIL / partial / 분야별 보류 | HOLD / 메뉴 없음 | FAIL |

모든5개 cohort의 기계/응답 계약은 PASS다. 마지막 근거 검토의 사실 일치·해석 범위·메모 일치는 본문과 선택 답 모두 PASS다. 4의 r1 메모 불일치는 r2에서 해소됐다. 5의 후속 답 제공은 메뉴가 없어 근거 검토자가 HOLD로 두었으며 평균으로 상쇄하지 않는다. 본문 질문 적합성 PASS는 충분한 개인별 답을 얻었다는 판정이 아니다.

| 실제 선택 답 | 질문 적합성·이해도·궁금증 충족 | 약속한 답 제공 | 답 이후 남은 메뉴의 흥미 |
| --- | --- | --- | --- |
| 1 도화의 풀이 방식 차이 | 모두 PASS / met | PASS | 없음 |
| 2 태극귀인의 복 | 모두 PASS / met | PASS | 배움/관계 질문 FAIL / 이미 답한 의미 반복 |
| 2 배움의 복과 관계 | 모두 PASS / met | PASS | 태극 질문 PASS |

이는 대리 독자 에이전트의 판정이다. 실제 사용자의 클릭·만족이나 예측 정확도를 측정한 결과는 아니다. 최종 상세 결과는 등록된 증거 경로의 `review-r2/independent-review-summary.md`와 각 `cohort-N/report-final.json`에 보존한다.

## 남은 원인과 다음 보강 범위

문장이 쉬워진 것과 사주풀이가 충분해진 것을 구별해야 한다. 마지막 검토에서도 “돈과 보상에 연결해 보는 글자는 겉에 1곳, 안쪽에 1곳 있어.”는 위치·개수 확인으로 읽혔다. 직업의 “당장 남은 보상과 쌓인 경험은 따로 볼 필요가 있어.”는 일반 조언으로 읽혔다. 조건별 문단을 개인별 결론과 적용 조건으로 통합하는 판단 단계가 필요하다. 분야/기간 결론을 뒷받침할 규칙은 별도 근거·반례 검토를 거쳐야 하며 이번 문구 보강으로 새 예측을 만든 것은 아니다. 시간 미상 사례의 미충족은 입력 부족이므로 확정형 결론으로 해결하지 않는다.

추가 질문의 중복도 남았다. 태극 답변에 “이 복이 있다는 이유로 인간관계까지 모두 편해진다고 보지는 않아.”가 있는데, 남은 메뉴는 “배움의 복이 있으면 인간관계도 편하다는 뜻일까?”를 제시한다. 실제 메뉴 선택은 현재 질문ID와 분야를 기준으로 거르며 이미 답한 의미까지 비교하지 않는다. 다음 보강은 답에서 이미 해결한 내용을 후속 메뉴에서 제외하고, 남은 질문이 새로 제공할 내용을 확인하는 데 필요하다. 현재의 본문 메뉴 흥미 PASS와 선택 뒤 중복 FAIL을 서로 상쇄하지 않는다.

프로젝트 스킬의 “새 snapshot/job으로 최대2회 재검토” 범위까지 진행했다. 이후 의미 변경은 새 작업/새 캡처/새 독립 검토가 필요하다. 이번 작업은 검증과 두 차례 보강의 완료이며, 전체 풀이 품질의 승인이 아니다.
