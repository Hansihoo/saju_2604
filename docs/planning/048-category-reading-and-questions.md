# 초기 전체 풀이와 분류별 질문

2026-10-09 사용자는 024/025/026에서 확인한 초기 순서의 풀이를 먼저 보여주고 각 분류 아래에 관련 질문을 붙이도록 요청했다.

## 목표·영향·경계

작업 유형은 기존 전체 해석 경로 연결과 표시/질문 배치다. 내 사주의 특징 → 연애·결혼운 → 금전운 → 직장·직업운 → 현재·다음 대운 순서를 유지한다. 사주팔자/으쓱 캐릭터, 전문 설명 기본 접힘, 질문 클릭 후 해당 답만 요청, 뒤로가기로 해당 분류에 복귀한다.

새 복수 근거 종합 판정이나 사건 시기 규칙을 추가하지 않는다. 계산 정책033과 카탈로그 critical 전체 보류는 유지한다. 047의 조건부 명식 계약은 여전히 별도 결정이다. 표준 입력의 기존 full report를 연결하며, 이를 효용/전문가 정확도 통과로 보고하지 않는다.

## 구현 계약

- 기존 `/saju/basic`은 모델 없는 기본 사실/용어 본문과 질문 API 호환을 유지한다.
- 새 `/saju/reading`과 `/saju/reading-stream`은 `initial_reading` 모드로 계산/전체 보고서 한 번을 실행한다. 별도 free preview 생성은 하지 않는다. 실제 계산/문장화 단계와 연결 heartbeat를 기존 stream으로 전송한다. stream 실패 후 자동 재생성하지 않는다.
- `critical`이면 모델 호출과 전체 해석을 하지 않고 `blocked_calculation` 분류/외부 경고/현재 기준의 사실 질문을 반환한다. 시간 미상은 시주/대운 제외를 유지한다.
- `category-reading-v1`은 기존 보고서의 본문과 명명된 기술 섹션을 서버에서 분리한다. React는 공급된 문장/Markdown/분류만 렌더링하며 명리 판정을 하지 않는다. 보고서/reading_sections 자체를 재작성하거나 검증 marker를 추가하지 않는다.
- 최초 독립 검토 FAIL 이후: 새 표시에서는 활성 규칙 없는 금전 일반 장문/오행 개수로 만든 소비 성향/대운별 재무 판단을 `needs_rule_review`로 보류한다. 동일 재성 사실 추출을 재사용해 겉/안쪽 개수와 해·달·날·시간 위치를 본문에 직접 제공하며 글자·십성·집계 방식은 메모에 둔다. 이 사실을 유익한 금전 예측으로 평가하지 않는다. 현재·다음 제목에 맞춰 다음 대운의 실제 계산 경계/글자를 덧붙이지만 좋은 사건 시기의 판정은 아니다. KO/EN 기술 제목을 메모로 옮기고 '전문가 노트' 제목은 표시하지 않으며 참고/비예측 범위는 메모 밖에 둔다.
- category copy `2026-10-09.2`와 전용 `calculation_notices`는 해석 보류 상태에 맞는 안내를 공급한다. 기존 `/saju/basic`의 문구/버전은 유지한다. 새 UI는 서버 notice를 우선 표시하고 반복된 분류별 보류 본문은 숨긴다. 메모·대운 경계 설명·금전 위치는 새로운 명리 판정이 아니다.
- 질문 `category`는 서버가 공급한다. `chart.pillars` 사실 질문을 core에 추가하고 기존 도화→love, 재성→wealth, 올해 글자→career, 현재/다음 교체일→luck_flow를 배치한다. 올해 글자는 직장 평가/보상 시기의 답이 아니다.
- 새 pillar 질문의 사실 추출/용어/지원 범위를 포함한 질문 facts/knowledge/rules/copy는 각각 `2026-10-09.1`, format은 `basic-question-reading-v2`다. 기존 해석 카탈로그의 규칙/문구 버전은 바꾸지 않는다. category 표시 copy/format, 진입 표시 버전은 독립 관리한다. 질문 결과의 버전 불일치 재입력 경로를 유지한다.
- 모델 가능 endpoint에는 fallback 검증 guard/private no-store를 적용한다. 요청 로그는 기존 PII 설정을 따르고 provider/응답 모드만 metadata로 기록한다.

## 위험과 검증

처음부터 전체 보고서를 기다리므로 모델 없는 기본 화면보다 대기가 길어진다. 기존 진행 UI를 연결하고 모델 호출은 하나로 한정한다. 정확한 실시간 Codex 지연/비용은 아직 측정하지 않았다.

기존 full fallback은 정상 입력에서 네 분류가 단일 feature/4역할로 덮어써지고 금전에는 일반 장문 조언이 남아 있다. 새 표시에서는 위 금전 본문을 보류했지만 기존 legacy 응답 자체는 변경하지 않았다. 이 연결만으로 초기 정보 깊이나 효용이 회복된 것은 아니다. 일반 조언을 늘리거나 과거 휴리스틱 날짜를 복구하여 통과시키지 않는다.

검증은 provider fallback을 격리한 API/stream/critical/unknown/호환·범위 검사, 타입/빌드, 실제 모바일 분류/메모/질문/복귀, fallback-only 사용자 시나리오, 동결된 실제 본문의 독립 질문자·답변자·감독관 검토다. 기존 임계 보류 입력의 본문 효용 실패는 code PASS로 상쇄하지 않는다. live Codex 문구 의미·실사용자 흥미·전문가 정확도는 별도다.

실행/콘텐츠 검토 결과는 PROJECT_STATUS/WORK_LOG에 기록한다. 새 snapshot/job/review를 생성하고 과거 실패/보류/통과는 보존한다.

## 실행 결과와 미완료 범위

- 전체 API 466개는 작업 중간 체크포인트에서 통과했다. 마지막 표시/문구 변경을 포함한 관련 API 53개, 웹 타입/빌드, 읽기 helper14 및 진행 계약8이 통과했다. 사실 질문 19개·기본 본문4개에서165검사가 통과했고 최신 분류 캡처4개/구조12검사도 통과했다.
- fallback-only 사용자 시나리오는456 PASS/3 WARN/기존 음력 유효30일 FAIL이다. 이 기존 계산 문제를 이번 표시 변경으로 수정했다고 보고하지 않는다. 검증 모델 호출은0이다.
- 실제 IAB에서 합성 정상 KO/EN 결과, 다섯 분류/관련 질문, KO 질문 답/원래 분류 복귀, 닫힌 메모 초기화, KO/EN320px 메모 펼침의 가로 넘침 없음 등을 확인했다. 서버 버전 변경 후 옛 응답은 재입력 안내가 나왔고 새 응답에서는 질문이 정상 반환됐다. 초반 HMR의 새 notices 필드 누락 오류는 호환 접근으로 수정했다.
- 독립 질문자·답변자·감독관 r1/r3/r4/r5 검토와 최종 합계는 모두 FAIL이다. 금전 일반 판정, 다음 구간 누락, critical 안내 불일치는 보강했지만 일반 입력의 내 특징/연애/직장/현재 대운은 기존 단일-feature 정책과 일반 조언이 중심이라 효용이 회복되지 않았다. 마지막 r5는 같은 본문에 실제 지장간 원본 사실 projection을 보강해 이전 금전 사실성 HOLD를 해소한 검토이며 기존 실패 기록을 보존한다. 실제 제천 경계 입력의 사주팔자·해석 보류/재성 질문도 브라우저에서 확인했다. 가상 대리 검토가 실제 흥미 검증을 대신하지 않는다.
- live Codex 결과 의미/실사용자 흥미/전문가 정확도는 검증하지 않았다. 기존 Codex6.1 Sol/xhigh 실행 설정으로 복원하되 검증만을 위한 모델 생성은 하지 않는다. 1988-11-20 23:30 제천 입력은 날짜 기준 차이로 해석 보류를 유지하며, 조건부 명식/새 복합 판정/미래 시기 규칙은047의 별도 작업이다.
