# 034. 도깨비 사주 모바일 경험

## 목표와 적용 범위

사용자가 모바일로 들어와 궁금한 주제를 먼저 고르고 출생 정보를 입력한 다음, 선택한 풀이와 표정이 들어간 카드 한 장을 저장·공유한다. 승인된 한 뿔의 연보라 도깨비 9종을 사용한다. 화면은 캐릭터와 기능 중심으로 구성하고 서비스 이름·가입 안내·홍보 문구를 표시하지 않는다. 주제 선택과 출생지의 도메인 분석은 [035](035-topic-first-reading.md)를 따른다.

이번 변경은 실제 `/` 서비스의 UX 구현이다. 계산 엔진, API 계약, LLM provider 설정은 유지한다. `/design-lab`은 과거 문서 스타일 비교용으로 남으며 새 경험의 시작 화면은 아니다.

## 핵심 동선

`첫 방문/주제 선택 → 생일/달력/성별 → 출생 시간/출생지 → 실제 풀이 대기 → 선택한 주제 결과 → 카드 표정 선택 → 저장/공유`

| 화면 | 사용자에게 먼저 보이는 것 | 주요 행동 |
| --- | --- | --- |
| 첫 방문 | 캐릭터, 핵심 한 문장, 질문이 있는 네 주제 버튼 | 오늘의 사주 / 이성·연애 / 일·돈 / 내 성격 선택 |
| 입력 1/2 | 출생 정보 제목, 생년월일, 양력/음력, 성별 | 다음 |
| 입력 2/2 | 고른 주제, 출생시간 또는 미상 선택, 태어난 곳 검색 | 선택한 주제 보기 |
| 대기 | 표정이 바뀌는 캐릭터, 선택한 주제 읽는 중, 점 애니메이션 | API 결과가 오면 바로 전환 |
| 결과 | 선택한 주제의 헤드라인, 강조된 조언, 전체 본문과 작은 분석 노트; 오늘은 실제 날짜 포함 | 다른 주제로 이동 / 카드 만들기 |
| 공유 | 실제 헤드라인 + 고른 주제의 조언 + 고른 표정 | PNG 저장 / 지원 기기에서 공유창 열기 |

### 사용자 시나리오

1. 지민은 모바일로 접속해 캐릭터·한 문장·네 주제가 있는 단일 화면에서 `이성 · 연애`를 고른다. 표정 선택은 상단의 캐릭터 아이콘에서 연다.
2. 숫자로 생일을 입력한다. `19970918`은 `1997-09-18`로 정리된다. 음력일 때만 윤달 선택이 나온다.
3. 태어난 시간을 모르면 미상을 선택한다. 태어난 도시를 검색 결과에서 고르며 선택 후 체크 표시를 본다. 현재 사는 곳을 받지 않으며 임의 문자열을 제출하지 않는다.
4. API 처리 중 “이성 · 연애 읽는 중”과 캐릭터 표정을 본다. 가짜 진행률이나 강제 대기 시간을 넣지 않는다.
5. 연애 주제의 실제 제목·조언·본문 전체를 바로 읽는다. 아래에는 작은 `분석 노트`로 명식 근거와 해석 기준을 표시한다. 다른 주제로 이동할 때 추가 LLM 호출을 하지 않는다. `오늘의 사주`로 이동하면 실제 일진 계산의 날짜·헤드라인·조언을 읽는다.
6. `카드 만들기`를 누른다. 수줍은 표정을 골라 1080×1350 PNG를 저장하거나, 파일 공유가 가능한 기기에서는 시스템 공유창을 연다.
7. 카드 문구를 공유하면 서비스 시작 URL이 함께 들어간다. URL은 타인의 개인 결과를 여는 링크가 아니다. 이미지에는 서비스 이름·슬로건·URL을 넣지 않는다.

## 정보 계층

- 첫 화면은 캐릭터·한 문장·네 주제 버튼으로 구성한다. 주제마다 짧은 질문과 표정을 사용하며 누르면 바로 입력으로 이동한다. 예시 카드, 부가 홍보, 푸터를 두지 않는다.
- 상단은 아이콘 기반 메뉴다. 입력/결과에는 뒤로·처음으로 버튼을 두며, 표정 선택은 캐릭터 아이콘으로 표시한다. 아이콘에는 접근성 이름을 제공한다.
- 입력은 2단계로 나누되 계산에 필요한 정보를 생략하지 않는다. 뒤로 이동하거나 `/stickers`에 다녀와도 현재 메모리의 입력값을 유지한다.
- 입력의 반복 설명·저장 안내를 제거한다. 필드명, 선택 주제, 선택 상태, 형식 오류와 시간 미상에 따른 제한 안내는 제공한다. 출생지에는 “출생지로 태어난 시각을 보정해요.” 한 줄을 표시하고 체크와 스크린리더 상태 안내로 선택을 확인한다. 출생지 미선택은 요청 전에 차단하고 입력으로 초점을 옮긴다.
- 결과는 **헤드라인 → 주제 → 강조된 조언 → 전체 본문 → 분석 노트** 순서다. 본문과 성격 요약의 모든 문단을 표시하며 말줄임·펼치기 버튼을 두지 않는다. 강조된 조언만 명조 계열의 서체를 사용해 본문 고딕과 구분한다.
- 본문 아래의 `분석 노트`는 작은 정적 영역이다. 명식 근거와 해석 기준을 차분한 전문 문체로 표시하고, 위의 조언을 다시 반복하지 않는다. 접기·숨기기 상태는 없다. 서버의 확인된 `basis_explanation`을 사용하고, 이전 응답/다른 provider에서 설명이 없으면 제공된 근거만 표시한다. 프론트는 단서를 새 해석으로 추측하지 않는다. 이는 사용자의 최신 전체 표시 요청에 따라 이전 접기 버전을 대체한 것이다.
- 결과 주제는 `오늘의 사주 / 이성·연애 / 일·돈 / 내 성격 / 시기의 흐름`이다. 네이티브 버튼 기반 탭과 방향키·Home·End 이동을 지원한다. 선택은 서비스 상태에 유지해 출생 정보 수정과 표정 갤러리 왕복에도 이어진다.
- 오늘의 사주는 `period_flows.today`를 메인 결과와 공유 카드로 보여주며 API의 날짜를 함께 표시한다. 오늘/월간 전체 흐름도 보조 영역에서 볼 수 있다. 월간 계산 기간은 양력 월과 다를 수 있어 `지금의 월간 흐름`과 API가 반환한 적용 날짜 범위를 표시한다. 전체 풀이는 명시적인 버튼 클릭 후 기존 상세 API로 요청한다.
- 출생시간 미상 안내는 결과 위쪽에 직접 표시한다. 그 밖의 제한·주의 문구는 `풀이 참고사항`에서 읽을 수 있다.
- 공유 버튼은 모바일 하단에서 접근할 수 있도록 두며 safe-area와 본문 하단 여백을 확보한다.
- 공유창은 카드 미리보기·표정 변경·저장/공유 버튼을 중심으로 한다. 서비스 이름과 반복 도움말을 두지 않는다. 오류·준비 상태·복사 실패 대체 경로는 유지한다.

## 캐릭터와 말투

| 역할 | 표정 | 목적 |
| --- | --- | --- |
| 첫 방문/결과의 나 | 사용자가 고른 표정, 초기 능청 | 친밀한 브랜드 인상과 사용자 취향 |
| 생일 입력 | 방긋 | 입력을 가볍게 시작 |
| 시간/지역 입력 | 깜짝 | 두 번째 단계의 리듬 변화 |
| 대기 | 졸림 → 깜짝 → 방긋 | 실제 기다림에 작은 리액션 |
| 성격/연애/일과 돈/흐름 | 능청/수줍/시큰둥/깜짝 | 주제 구분용 표현 |
| 입력 오류 | 울먹 | 비난 없이 다시 입력하도록 도움 |
| 공유 | 사용자가 직접 선택 | 한 장에 자기 취향 담기 |

표정은 UI 역할에 배치한 것이다. 사용자의 운세가 좋다/나쁘다거나 성격이 특정 감정이라고 판정한 값이 아니다.

시작 문장은 “사주에 있는 그대로 말해줄게”다. 사용자를 비꼬거나 탓하지 않는다. `오늘, 밀고 갈까 쉬어 갈까?`, `연애할 때 난 어떤 타입?`처럼 실제 풀이 범위와 연결되는 짧은 질문으로 주제를 고른다. 버튼·필드명은 `다음`, `태어난 곳`, `카드 만들기`처럼 기능을 직접 표현한다. 캐릭터 표정과 실제 풀이 내용으로 친근함을 전달한다. 설명을 위해 대사를 여러 줄 반복하지 않는다.

### 계산에 충실한 솔직함

핵심 문구는 **“사주에 있는 그대로 말해줄게.”**다. 계산에 충실한 태도는 한 문장과 실제 입력 처리로 전달한다. 모르는 정보는 확정하지 않으며 해석이 반드시 맞는다거나 미래를 확정한다는 약속은 하지 않는다.

사용자가 듣기 좋은 말만 요구한다거나 결과에 항의한다고 가정하지 않는다. 재미는 캐릭터 표정과 풀이 내용에서 만들며, 실제 행동에 필요한 안내만 표시한다.

| 접점 | 문구 | 실제 동작과의 연결 |
| --- | --- | --- |
| 첫 화면 약속 | “사주에 있는 그대로 말해줄게.” | 계산 엔진의 값과 풀이 표현을 분리하며 LLM은 사주를 다시 계산하지 않는다. |
| 생일 입력 | 생년월일·달력 기준·성별 필드 | 계산에 필요한 실제 입력을 먼저 받는다. |
| 지역 입력 | 도시 검색·선택 확인 체크 | IANA 시간대/DST와 기존 지역 경도 보정을 실제 계산에 사용한다. |
| 시간 미상 | “시간이 필요한 풀이는 제외할게.” | 미상 시각의 내부 placeholder를 확정값처럼 안내하지 않고 시간 의존 풀이를 제외한다. |
| 대기 | “사주 읽는 중” | 실제 API를 기다리는 상태이며 가짜 진행률을 뜻하지 않는다. |

근거는 [현재 계산 규칙](033-current-calculation-rules.md)의 입력·시간 보정, 미상 처리, 계산과 LLM의 경계다. 아직 검토 중인 계산 기준을 모두 검증 완료했다고 표현하지 않는다. 전문 용어·정확도 수치·검증 배지를 화면에 반복하지 않는다.

개인별 풀이 문장은 API가 반환한 값을 사용한다. 프론트에서 모든 사용자에게 같은 매운 진단을 덧붙이지 않는다. 개인 풀이의 말투는 별도 버전의 LLM 말투 프로필과 검증 기준으로 다듬을 후속 범위다.

## 공유 및 데이터 경계

- 공유 이미지는 결과 헤드라인, 선택한 주제 라벨/조언, 선택한 캐릭터를 담으며 오늘 카드에는 적용 날짜를 포함한다. 서비스 이름·슬로건·생년월일·시간·지역·trace ID를 포함하지 않는다.
- PNG는 브라우저 Canvas에서 생성하며 서버 업로드·개인 결과 링크 저장을 추가하지 않는다.
- 파일 공유는 `navigator.canShare({files})`가 가능할 때만 표시하고 사용자의 버튼 클릭에서 `navigator.share()`를 호출한다. 미지원 기기는 이미지 저장과 문구 복사를 제공한다. 복사 실패 때 직접 선택할 수 있는 문구를 표시한다.
- 공유창에서 보내기를 완료하는 행동은 사용자가 한다. 개발 검증에서 메신저로 실제 전송하지 않는다.
- 출생 정보와 결과는 현재 앱 메모리만 사용한다. 새로고침하면 다시 입력해야 한다. 기존 버전의 localStorage는 표정 ID만 보관한다.

기술 근거: [MDN Web Share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share), [canShare](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare), [Canvas toBlob](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob).

## 다음 다듬기 기준

1. 첫 화면에서 사주 풀이임을 이해하는지, 한 문장과 네 주제 버튼이 모바일 첫 화면에 들어오는지 확인한다.
2. 한 입 풀이 문장의 길이와 구체성을 API 말투 버전에서 조절한다. 관찰되는 습관 → 근거 있는 설명 → 행동 하나를 유지하며 점수·공포·사건 확정 표현을 만들지 않는다.
3. 사용자가 실제로 공유하고 싶은 한 문장을 고르는지 확인한 뒤 카드 정보량과 얼굴 크기를 조정한다.
4. 회수할 지표가 필요하면 시작/입력완료/주제선택/카드저장 같은 행동만 정의한다. 출생 정보·풀이 원문을 분석 이벤트에 넣지 않는다. 이번 변경에는 외부 분석 전송을 추가하지 않았다.

## 검증과 검토 화면

분석 노트와 전체 표시의 최신 검증은 [USER_STORY_VERIFICATION](../ai/USER_STORY_VERIFICATION.md)에 기록한다. 아래 결과와 근거 JPEG는 최신 전체 표시 화면으로 갱신한다. 이전 접기 버전은 API 303개·관련 79개, 웹 타입/빌드·helper 10개 및 실제 KO/EN 모바일 펼침/숨김을 확인했던 기록이다. 전체 HTTP 판정은 기존 음력 입력 실패로 `Needs review`를 유지한다.

주제 선택·출생지 안내의 최신 검증은 [035](035-topic-first-reading.md)에 기록했다. 첫 화면·입력·결과·공유·PC 검토 JPEG는 주제 선택형 UI로 갱신했다. 아래 문구 최소화·초기 UX 검증은 이전 회차 기록이다.

문구 최소화 후 `pnpm build:web`의 TypeScript 검사와 Vite 빌드, `git diff --check`를 통과했다. Chrome 320/390/1440px에서 한/영 첫 화면, 아이콘 탐색, 표정 선택, 2단계 입력, 시간 미상/복원, 지역 선택 확인 체크, 실제 fallback 풀이, 주제 전환, 버튼 클릭 이후의 전체 풀이 요청을 확인했다. 공유 카드의 실제 이미지 크기는 1080×1350이며 표정 변경 시 재생성된다. ESC로 공유창을 닫으면 body 스크롤이 복원된다. 가로 넘침과 검증 시작 이후의 런타임 경고·오류는 없었다. 이번 문구 제거에서는 새 PNG 파일 다운로드와 메신저 전송을 수행하지 않았다.

최초 UX 구현에서는 알려진 시간/미상 입력, 오늘/월간 카드 표시, 표정 갤러리 왕복 후 결과/상세 읽기 유지와 실제 PNG 파일 저장(1080×1350)도 확인했다.

개발 도중 custom hook에 ref를 추가하면서 HMR의 기존 hook 순서와 충돌했다. 새로고침한 최종 흐름에서는 런타임 오류가 없었다. PNG 다운로드 이벤트 대기는 timeout이었지만 실제 저장 파일·파일 시각·PNG header·크기와 이미지 표시를 확인했다. 시스템 공유창은 지원 여부를 감지해 표시하며, 실제 메신저 전송/Android·iOS 실기기 확인은 이 작업에서 하지 않았다. 전체 backend 회귀 테스트는 계산/API를 수정하지 않아 재실행하지 않았다.
