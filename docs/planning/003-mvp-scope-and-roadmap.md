# MVP Scope And Roadmap 003

## 목적
- 제품 범위, 단계별 목표, 구현 착수 전 필요한 정책 질문을 정리한다.
- 개발 전에 "무엇을 먼저 만들고 무엇을 나중에 미룰지"를 고정한다.

## MVP 정의
- 첫 사용자가 자신의 기본 사주 해석을 신뢰감 있게 받아보는 경험을 완성하는 것이 MVP 목표다.
- MVP는 단순히 결과를 출력하는 것이 아니라, 계산 정확성과 해석 구조의 신뢰를 함께 보여줘야 한다.

## 1단계 범위
- 입력:
  - 양력/음력 선택
  - 생년월일
  - 생시(HH:mm)
  - 성별
  - 지역 검색형 선택
- 처리:
  - 시간 보정
  - 사주팔자 계산
  - 만세력 생성
  - 분석 엔진 점수/등급 산정
  - LLM 기반 기본 해석 생성
- 출력:
  - 요약
  - 강점
  - 약점
  - 연애운
  - 직업운
  - 금전운
  - 대운 흐름
  - 행동 조언
  - 가능하면 계산 근거 요약
  - 오행/십성/대운 상세 근거 펼침

## 2단계 범위
- 오행 시각화
- 대운 시각화
- 추가 질문 기능
- 결과 설명의 인터랙티브 확장

## 3단계 범위
- 궁합
- 고급 분석
- 세부 리포트 확장

## 개발 순서 기본안
1. 입력 정책 확정
2. 시간 보정 모듈 검증 전략 수립
3. 사주 계산/만세력 데이터 구조 확정
4. 분석 엔진 규칙 초안 작성
5. LLM 출력 스키마와 안전장치 설계
6. MVP 화면/API 명세 작성
7. 첫 구현 회차 시작

## 구현 전에 닫아야 할 정책 질문
- 양력/음력 변환 책임을 어디서 맡을지
- 성별 입력값 정책을 어떻게 정의할지
- 시간 보정 실패 시 재입력을 유도할지, 대체 계산을 허용할지
- 사용자에게 점수/등급 산정 이유를 어디까지 공개할지
- 출생시간 기본값 `00:00`일 때 비활성화할 계산/화면 범위를 어디까지 둘지

## 도메인 검증 우선순위
- 1순위:
  - 시간 보정 정확도
  - 지역 -> IANA 타임존 매핑 정확도
- 2순위:
  - 사주 계산 결과 검증
  - 만세력 데이터 정합성
- 3순위:
  - 점수/등급 산정 규칙 일관성
  - LLM 표현 정책 준수

## 이번 회차 결정
- MVP는 "개인 단일 해석 경험"에 집중한다.
- 계산 정확성과 설명 가능성을 동시에 보여주는 것이 1차 목표다.
- 구현 순서도 UI보다 계산과 정책 확정을 먼저 둔다.
- 양력/음력을 모두 지원하고 기본값은 양력으로 둔다.
- 생시는 `HH:mm` 필수 입력으로 받는다.
- 출생시간 미상 시 기본값 `00:00`으로 입력하고, 시주 기반 결과는 비활성화한다.
- 한국을 초기 기본 지역으로 둔다.
- 저장 없는 비회원 1회 조회로 시작한다.
- 사용자에게는 요약형 결과를 우선 노출하고, 내부 점수/등급 엔진은 유지한다.
- 지역 입력은 자동완성 검색 후 선택 방식으로 고정한다.
- 오행/십성/대운은 접힌 상태의 상세 근거 섹션으로 제공한다.

- 시주 비활성화가 영향을 주는 분석 항목 목록
