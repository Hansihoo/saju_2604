# 질문 선택 전의 유익한 기본 본문

후속 2026-10-09: 실제 사용자가 046을 거친 본문을 방법 설명뿐이라며 거절했다. 아래 기술/역할 PASS를 유용한 풀이 완성으로 확대하지 않는다. [047](047-reading-utility-recovery.md)에 vocabulary-only/규칙 미적용 원인과 효용 FAIL, 실제 풀이 복구에 필요한 별도 규칙/계약을 기록했다.

후속 표시 보정: [046](046-plain-reading-and-folded-evidence.md)이 쉬운 본문과 접힌 전문 근거의 최신 계약이다. 이 문서의 기존 전문 용어/정밀 날짜 본문은 `memo_sections`에 보존하며, always-visible `sections`는 쉬운 문장으로 표시한다.

2026-10-08 직접 피드백: “질문 나올땨 본문도 유용한 정보가 있어야지”. 043의 기본 명식과 질문 메뉴만으로는 선택 전에 얻는 정보가 부족했다.

## 목표와 영향 범위

출생 입력 → 계산된 명식 → 항상 보이는 개인별 본문 → 지원 질문 → 상세 답/메모/공유. 기본 본문을 읽는 데 추가 클릭을 요구하지 않는다. 이번 작업은 API의 추가 본문 계약과 React 표시, 제품 피드백/검증 문서 보강이다. 기존 계산 정책과 질문 endpoint·선택 답·공유를 보호한다.

본문은 현재와 다음 대운의 확인된 날짜·글자와 용어 차이, 올해와 일간의 관계, 돈을 설명할 때 쓰는 재성의 겉/지장간 위치, 도화의 방법별 결과를 연결한다. 개인별 실제 값과 의미를 설명하며, 매 문단에 일반적인 숙제를 붙이지 않는다. 전문 근거는 작은 기본 닫힘 `풀이 메모`다.

## 사실과 설명의 경계

- 서버가 같은 `report_mode=none` 계산 snapshot으로 본문을 만든다. 기본 읽기에 새 모델·HTTP 요청을 추가하지 않는다.
- 일상 의미는 기존 프로젝트 카탈로그의 일반 용어 배경이다. 기존 `luck_flow` 판정 규칙을 새로운 날짜/상황에 적용하거나 전문가 승인으로 바꾸지 않는다.
- 날짜는 대운/입춘의 계산 경계이고, 사건 발생일이 아니다. 재성 위치 수는 돈복의 크기/소득이 아니며 도화 방법의 개수를 합쳐 매력/만남 확률을 만들지 않는다.
- 시간 미상에서는 대운/시주를 제외하고 재성·도화는 확인된 세 기둥만 설명한다. critical에서는 현재 선택된 정책의 사실과 용어 설명만 제공하며 중요 한계를 메모에 숨기지 않는다.
- 한 섹션의 자료가 없으면 유효한 명식 전체를 실패시키지 않는다. 누락 범위는 명시하고 제공할 수 있는 정보만 남긴다.

## 계약과 유지보수

`/saju/basic`에 `basic_reading`을 추가한다. 제목·주요 문장·본문 섹션·메모·한계·fact 목록·source_context·독립 facts/knowledge/copy/format 버전을 갖춘다. 섹션의 fact_ids가 실제 공급된 fact를 가리키고 source_path는 raw basic 응답에서 그대로 확인 가능해야 한다. 기존 `question_flow.versions`와 selected-question 계약은 유지한다.

`basic_reading.py`는 기존 사실 추출 helper를 재사용하는 별도 조합 모듈이다. UI는 supplied text를 문단으로 나눠 표시하며 사주 판정을 하지 않는다. 본문은 모두 노출하고 중요한 한계는 한 번 명확히 표시한다.

최종 기본 본문 버전은 facts `basic-reading-facts-2026-10-08.1`, knowledge `basic-reading-knowledge-2026-10-08.1`, copy `basic-reading-copy-2026-10-08.2`, format `basic-overview-v1`이다. 이 버전은 기존 선택 질문의 버전과 별개이며 기존 질문 답을 무효화하지 않는다. 메모가 사용했다고 설명하는 자료는 실제 포함한 섹션과 반드시 일치해야 한다.

## 검증 방법

신규 본문 단위/실제 계산 테스트, 기존 질문/검증 모듈 회귀, 웹 타입·빌드와 fallback-only 사용자 시나리오를 실행한다. 실제 모바일 KO/EN의 본문 위치·문단 표시·접힌 메모·질문 진입/복귀·시간 미상·가로 넘침을 확인한다.

`verify_question_flow`는 실제 basic 본문도 snapshot에 담는다. `-ReviewScope basic`은 새 본문 4사례만 역할 job에 제공하면서 실제 실행한 기존 질문 검사도 보존한다. 역할 prompt/rubric `.3`은 선택 전 얻는 정보와 미래 시기 욕구 충족을 분리한다. 새 snapshot에서 질문자는 유익성/이해도, 답변자는 문구/개인별 설명, 감독관은 사실/범위/메모를 독립 검토한다. 실제 사용자 흥미/외부 전문가·예측 정확성 검증은 별도다.

## 검증 결과

구현과 기본 본문 검증을 완료했다. copy `.1` 시점의 API 전체 446개가 통과했고, 최종 copy `.2`의 기본 본문 14개 + 기존 질문 22개(총 36개) 회귀가 통과했다. 실제 ASGI는 기본/선택 답 19사례를 실행하고 기본 본문 4사례를 리뷰 snapshot에 담았다. 137개 전역 검사와 본문 fact 대조는 모두 통과했다. 검증 모델 호출은 0회다.

웹 타입·빌드, 기존 reading helper 14개/progress 7개와 리뷰 모듈 15개가 통과했다. React 점검에서는 순수 렌더러 분리, 직접 import, 제목 연결과 native details를 확인했으며 본문에 새 effect/요청/의존성을 추가하지 않았다. IAB KO390/KO320/EN320에서 본문이 질문 앞에 항상 표시되고 메모는 기본 접힘이며 선택/복귀, 입력 보존과 시간 미상 세 섹션 범위가 유지됐다. 영문 미상 메모를 실제 펼쳐 대운을 사용했다고 주장하지 않음을 확인했다. 가로 넘침이나 새 warn/error 로그는 없었다. viewport·언어·사용자의 남성/제천/23:30 입력을 복원하고 로컬 서비스를 유지했다.

첫 역할 검토 r1은 질문자 HOLD/답변자 HOLD/감독관 FAIL이었다. 시간 미상 메모가 제외한 대운까지 사용했다고 설명한 오류와 반복 용어 설명을 고친 뒤 새 snapshot/job을 생성했다. 최종 r2는 질문자 PASS/답변자 PASS/감독관 PASS, 종합 PASS다. `primary_future_need_met=false`, `user_interest_validated=false`, `prediction_accuracy_validated=false`는 유지된다. 답변자는 본문 작성자 자기검토이며 나머지 두 역할은 다른 역할의 결과 없이 지정 job만 검토했다. 완전한 도구 격리 맹검은 아니다.

증거는 등록된 `.dev-runtime/question-flow-20261008/`의 `basic-body-r1/r2.json`, 각 jobs/reviews, `basic-body-review-report-r1/r2.json`, `basic-body-r2-*.png`에 보존한다. r1 증거를 덮어쓰지 않았다. 질문자는 선택 전 정보 유익함을 통과시키면서 문체가 설명서에 가깝고 흥미·공유 반응은 아직 검증되지 않았다고 남겼다. 이 후속 편집/실사용자 검토와 미래 기간 규칙 보강은 별도 작업이다.

fallback-only 기존 사용자 시나리오는 456 PASS/3 WARN/1 FAIL이다. FAIL은 기존 유효 음력 30일 입력 오류이며 이번 본문 변경으로 해결하지 않았다. 실사용 흥미, 외부 전문가 승인과 만남·취업 시기 지원은 이 검증으로 확보되지 않는다.
