# 074. 만세력 하단 시트와 원격·Codex 테스트 인계

## 목표와 범위

사용자는 만세력 버튼 시안 중 하단 시트를 선택한 뒤 “지금까지 내역 원격까지 반영하고. codex로 내가 테스트할 수 있도록 해줘”라고 요청했다. 결과 화면의 만세력 보기 버튼을 실제 API의 계산값에 연결한다. 이전까지 누적된 프로젝트 변경도 검토·커밋·원격 동기화하고, 기존 로컬 Codex 프로필을 실행해 사용자가 새 풀이를 테스트할 수 있게 한다.

프런트엔드는 `manse.pillars`, `manse.elements`와 기존 출생/지역/계산 안내를 표시한다. 별도 계산·새 점수·성격 판단·LLM 호출을 추가하지 않는다. 네 기둥/독음·천간/지지 오행, 접힌 십성·지장간, 겉글자 오행 개수와 범위, 접힌 입력·계산 기준을 제공한다. 시간 미상은 시주를 비우고 날짜 경계는 잠정 상태와 원본 안내를 보존한다.

## 구현과 위험

네이티브 dialog를 하단 시트로 사용한다. 바깥 클릭·닫기·Escape·풀이 이어 읽기로 닫고 초점을 원래 버튼으로 돌린다. 본문 스크롤은 유지하며 시트 내부만 스크롤한다. 작은 화면에서도 닫기와 복귀 버튼을 계속 사용할 수 있다. 공개 내부 점수/등급은 표시하지 않는다. 계산033과 종합/시기 보류는 바꾸지 않는다.

시안의 가상 명식은 제품 코드에 복사하지 않는다. 로컬 결과/인증정보/로그/검증 산출물은 ignored 경로에 남긴다. API 상용 기본과 로컬 Codex 프로필을 구별하고, 로그인 준비를 실제 생성 성공으로 보고하지 않는다. 사용자 테스트에 필요한 서비스를 유지하며 회귀 검증은 fallback-only로 수행한다.

## 검증과 인계

전체 API 회귀, 웹 타입/빌드·기존 helper, fallback 사용자 시나리오, 정상/시간 미상/날짜 경계의 실제 응답과 KO/EN 브라우저를 확인한다. 시트 열기/닫기/초점 복원·Escape·원국/오행·접힌 상세·좁은 화면·배경 스크롤을 점검한다. 결과 원문과 계산값의 일치는 실제 모델의 내용 효용 승인과 구별한다. 원격 커밋 일치와 Codex 서버 상태, 사용자 접속 주소를 함께 인계한다.

## 구현과 검증 결과

- `DokkaebiManseSheet`와 결과 버튼을 연결했다. `manse-sheet-2026-10-24.1`은 표시 버전이며 계산/knowledge/rules는 바꾸지 않는다. 원국 값과 겉글자 오행은 실제 서버 응답을 그대로 사용한다.
- 전체 API580개(261.063초), 웹 reading14/progress8, TypeScript와 격리 production build PASS다. 기존 테스트에서 출력하는 의도적 실패 fixture는 unittest 자체 실패와 구별했다.
- fallback 실제HTTP 정상KO/EN·시간미상·날짜경계4결과를 동결해 390/320/1280의12조합을 별도 로컬Chromium으로 확인했다. 천간/지지·오행이 원본과 같고, 미상 시주/십성/지장간은 비어 있으며 닫기·Escape·복귀·원국/오행·펼침·초점/스크롤복원·가로넘침/바닥 버튼이 PASS다. 시트 조작 POST0/제품 모델호출0이다. 최종 EN 행 라벨 폭을 보정하고 같은 검사를 재실행했다.
- 앱 내부 브라우저는 native bridge 신뢰 오류로 HOLD다. 별도Chromium의 실제 화면 검사와 구별하며 앱의 연결 신뢰 설정을 바꾸지 않았다.
- fallback 사용자 시나리오는456 PASS/3 WARN/기존 `known_issue.valid_lunar_day30` 1 FAIL이다. 실패를 이번 시트의 문제나 전체 성공으로 바꾸지 않는다. 기존 공개 응답 내부점수 노출/전체 풀이 내용 FAIL·미지원 종합/시기·상용 키누락도 이번 표시로 해결되지 않는다.
- 기존 비활성 서비스 metadata/로그를 registered evidence에 보존하고 fallback 검증 후 `pnpm dev:codex`로 전환했다. Codex 로그인/CLI준비 정상, gpt-6.1-sol/xhigh 설정, API8000/Web5173 정상이다. actual provider endpoint는 codex/fallback_only=false다. 실제 모델 추론은 사용자가 새 입력에서 테스트하며 이번 회귀 검증의 모델호출은0이다.

검증자료와 격리 빌드/브라우저 캡처는 등록된 `.dev-runtime/manse-ready-20261024-01a16679`에, 가상 결과4개는 개별 등록된 `.dev-runtime/local-results` 파일에 보존한다. API suite가 반환한 자체 임시 보고서는 완료 뒤 자동 제거되어 missing으로 장부에 기록했다. 실행중 테스트 환경과 결과는 정리 요청 전까지 유지한다.

## 원격 반영과 사용자 테스트

누적156파일을 `[UI] 사주 풀이와 만세력 조회·Codex 실행 반영` 커밋 `d74666d4fcd5d695cb8ff824c098fdebae1c2c3c`로 `origin/main`에 푸시했다. 원격 refs/heads/main과 로컬HEAD가 같은 해시임을 확인했다. 인증/로컬 env/실제 결과 스냅샷/임시 산출물은 커밋하지 않았다. 이것은 저장소 동기화이며 상용 API 키 복구나 배포의 실제 생성 검증이 아니다.

사용자는 `http://127.0.0.1:5173`에서 출생정보를 입력해 새 풀이를 실행한다. 원국이 달라질 수 있는 입력은 기존 보류를 유지한다. 풀이 뒤 **만세력 보기**를 누르면 같은 응답의 계산값이 시트에 표시된다. 로그인·현재 provider와 서비스 health는 정상이나 실제 Codex 모델 가용성/생성 결과는 새 입력의 응답으로 판단해야 한다. 저장된 가상4결과는 fallback/deterministic 고정본이므로 Codex 새 생성 결과로 취급하지 않는다.
