# 쉬운 본문과 접힌 풀이 메모

후속 2026-10-09: 실제 사용자가 이 본문을 방법 설명뿐이라며 거절했다. 아래 기술/역할 PASS는 역사로 보존하되 사용자 효용의 완료로 인정하지 않는다. [047](047-reading-utility-recovery.md)의 새 사례별 검증에서 실제 네 본문은 readability PASS/usefulness FAIL이며 독립 세 역할/합계 FAIL이다. 표시 기능은 유지하고 실제 개인별 풀이 복구 작업을 다시 연다.

## 목표와 범위

2026-10-08 사용자 피드백: “너무 어렵게 써서 뭔소리인지 모르겠어 근거자료는 펼치기로 숨기고 풀이한 내용을 보기 좋게 보여줘”. 044의 용어 설명 중심 본문과 045의 오행 집계 상시 표시는 이 요청에 맞춰 변경한다. 사주팔자와 으쓱 캐릭터는 상단에 유지한다.

이번 작업은 결과 문구·표시 계약·검토 입력의 변경이다. 계산 정책 033, 기간 판정, 사주 해석 규칙, provider, 모델, 공유 계약과 배포는 바꾸지 않는다. 생활 주제는 기존 카탈로그 분류를 쉬운 말로 옮긴 설명이다. 문구를 쉽게 바꾸면서 취업·연애 사건 시기, 돈의 크기, 성격을 새로 판정하지 않는다.

## 본문과 메모의 계약

- `BasicReading.sections`: 항상 보이는 쉬운 제목과 문단. 현재/다음 계산 구간, 올해와 현재 주제의 공통점·차이, 금전 표시의 실제 위치 차이, 도화 판정의 방법 차이를 개인별로 설명한다.
- `memo_sections`: 기존 한자·십성·정밀 구간 경계·지장간·도화 판정 설명을 보존한다. 같은 섹션 ID와 fact_ids를 사용한다.
- `memo`: 사용 자료와 계산 범위, 일간, 겉글자 오행 개수. 지장간 제외와 강약 판정이 아니라는 설명도 접힌 메모에 둔다.
- `notices` / `limitations`: 시간 미상, critical 경계와 사건 예측 범위를 본문 밖의 보이는 영역에 유지한다. 근거를 접는다는 이유로 중요한 계산 한계를 감추지 않는다.
- 선택 질문은 직접 답을 먼저 보여주고 기존 기술 `sections`와 메모를 한 개의 작은 기본 접힘 `풀이 메모`에 둔다. 질문 이동·새 결과에서 접힘을 초기화한다.

프런트엔드는 서버가 준 문장을 렌더링한다. 계산·용어 분류·위치 판정은 백엔드에 남긴다. native `details/summary`, 기존 터치·초점 스타일을 사용하며 클릭 시 추가 분석 호출을 하지 않는다. 기존 서버 응답 호환용 신규 필드는 optional로 받는다.

## 문구 재발 방지

한자와 전문 분류 이름으로 본문을 시작하지 않는다. “지장간에 재성 3곳” 대신 글자를 더 나눠 읽었을 때 태어난 해·달·날의 부분에 돈과 보상에 관한 표시가 있다는 뜻을 설명한다. 도화는 연애 풀이에서 참고하는 사주 표시라는 역할부터 설명하되 인기·성공 확률로 연결하지 않는다. 여러 해의 계산 구간이 바뀌는 시점과 실제 좋은 일이 생기는 시점을 혼동하지 않는다.

같은 분류의 일반 설명을 현재 구간과 올해 카드에서 그대로 반복하지 않는다. 서로 같은 주제인지 다른 주제인지 먼저 말한다. KO 조사 연결은 변수에 `야/라는/를`을 무조건 붙이지 않고 `쪽이야/쪽으로` 등 자연스러운 구문을 쓴다. 시간 미상 본문은 “세 기둥” 대신 “생년월일로 확인할 수 있는 부분”이라고 말하고 기술 범위는 메모에서 명시한다.

## 검증과 기록

API 정상·경계·시간 미상·KO/EN 본문에서 같은 fact/source_path와 메모 범위, 기존 정밀 경계와 위치, no-model-call을 확인한다. 웹 타입/빌드/helper/대기 회귀와 fallback-only user-story도 확인한다. 실제 모바일에서 기본 접힘·펼침·질문 이동·복귀·새 결과 초기화·좁은 폭의 넘침을 확인한다.

독립 질문자·답변자·감독관은 동결 결과만 받는다. 질문자는 보이는 본문만 받고 다른 역할은 원본 사실 투영과 접힌 메모도 비교한다. snapshot 전체는 보존하고, 검증 후 같은 사실을 answer/case에 두 번 보내던 중복만 제거한다. 큰 job은 헤더와 각 사례의 답/사실을 나누어 읽어 출력 잘림으로 사례가 누락되지 않게 한다.

초기 r1: 질문자 FAIL(미해설 도화·겉/안쪽), 나머지 두 역할 HOLD(출력 잘림으로 일부 사례 미검토). r2: 질문자 HOLD, 답변자 FAIL, 감독관 HOLD(시간 미상의 일주 확정 불가와 영어 지장간 층 설명). r3: 답변자·감독관 PASS, 질문자 HOLD(영어 구조 용어 잔존). 해당 지적을 수정하고 대운 메모에 기존 정확한 전환 시각도 보존했다. 역사 파일은 덮어쓰지 않는다. 최종 결과는 PROJECT_STATUS/WORK_LOG에 기록한다. 대리 검토의 PASS도 실제 사용자 흥미나 사주 예측 정확도의 인증이 아니다. 기존 fallback 음력 day-30 FAIL도 유지한다.
