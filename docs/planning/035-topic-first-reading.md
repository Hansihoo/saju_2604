# 주제를 먼저 고르는 사주 경험

## 도메인과 프로젝트 분석

- 사주의 네 기둥은 출생 연·월·일·시를 기준으로 세운다. 참고: [한국민족문화대백과 사주](https://encykorea.aks.ac.kr/Article/E0025957). 전통 명리 설명과 계산 구현의 일치는 예측의 정확성을 보증하는 의미가 아니다.
- 이 프로젝트의 `SajuPreviewRequest.region_id`는 출생지다. `preview_orchestrator.py`에서 선택 지역을 검증하고 출생일 당시 IANA 시간대/DST를 처리한 뒤 기존 지역 경도 보정을 적용한다. 현재 거주지를 출생지에 대신 넣지 않는다.
- 출생지 입력은 기존 2단계 폼의 두 번째 화면에서 이미 필수였다. 첫 화면에는 일반 시작 버튼만 있어 지역 입력과 주제 선택이 보이지 않았다.
- 사용자의 최종 확인에 따라 거주지 필드와 위치 권한은 추가하지 않는다. 도시 단위 출생지를 검색하고 후보 중 선택한다.
- `build_period_flows.py`는 출생 명식과 현재 일진/절기 월을 비교해 오늘·월간 흐름을 계산한다. 현재 날짜 기준은 기존 출생 지역의 시간대다. 브라우저 날짜나 무작위 문구로 바꾸지 않는다.
- 무료 미리보기에는 `core`, `love`, `work_money`, `luck_flow` 카드가 이미 있다. 오늘 결과도 응답의 `period_flows.today`에 있지만 접힌 보조 메뉴 안에 있었다.
- 현재 API는 상대방 출생정보를 받는 궁합 엔진이 아니다. 이성/연애 선택은 자신의 연애 성향·조언을 보여준다. 특정 상대의 감정이나 만남 확률을 만들어내지 않는다.

## 구현 범위

1. 첫 화면의 일반 시작 버튼을 오늘의 사주·이성/연애·일/돈·내 성격의 네 주제 버튼으로 교체한다. 짧은 질문과 승인된 표정으로 선택한다.
2. 선택 주제를 서비스 상태에서 유지해 폼·대기·결과·공유에 연결한다. 결과 탭과 출생 정보 수정 이후에도 같은 주제를 유지한다.
3. 두 번째 입력 화면의 출생지를 더 분명하게 표시하고 필요한 한 줄만 안내한다. 출생지를 선택하지 않으면 요청하지 않는다.
4. 오늘 결과는 실제 `period_flows.today`의 헤드라인·날짜·요약·조언을 메인 카드와 공유 카드로 제공한다. 다른 주제는 기존 개인별 미리보기 카드에 연결한다.
5. 계산 엔진·legacy 기본값·API 계약·LLM 호출 정책은 유지한다. 표시는 별도 UI 모델로 확장한다.

## 위험과 검증

- 오늘 결과와 성격 카드의 혼동, 선택 주제 유실, 공유 카드 주제 불일치, 출생지 미선택 요청, 모바일 버튼 넘침을 점검한다.
- 웹 타입 검사/빌드, 기존 기간 흐름·시간 보정 테스트, 실제 fallback API의 모바일/PC 동선과 날짜·탭·공유 카드·출생지 오류를 확인한다.
- 개발 중 진행 상태는 `docs/PROJECT_STATUS.md`와 `docs/ai/WORK_LOG.md`에 기록한다.

## 검증 결과

- `pnpm build:web`의 TypeScript 검사와 Vite 빌드, `git diff --check` 통과.
- 기존 기간 흐름 3건과 시간 보정/골든 10건, 총 13개 테스트 통과. 계산 엔진·API는 수정하지 않았다.
- Chrome 320/390/1440px에서 가로 넘침이 없었다. 320px 한국어/영어와 390px 한국어 첫 화면에서 네 주제 버튼 모두 첫 화면에 들어왔다.
- 합성 출생 정보로 실제 fallback API 동선을 확인했다. 오늘의 사주 선택은 실제 API 날짜 `2026년 10월 4일`, 일진 기반 헤드라인·요약·조언을 메인으로 표시했다. 오늘 공유 카드에도 같은 날짜와 조언이 들어간다.
- 출생지 미선택 시 요청 전에 오류를 표시하고 출생지 입력으로 초점을 옮겼다. 검색 후보 선택, 확정 체크, 시간 미상/시각 복원, 재입력 후 유지가 정상 동작했다.
- 이성/연애를 첫 화면에서 고르면 결과에서 연애 탭이 먼저 열렸다. 방향키로 일/돈 전환, 갤러리 왕복, 출생 정보 수정 이후에도 고른 주제가 유지됐다.
- 오늘 PNG 미리보기는 실제 1080×1350 크기였다. 공유창을 닫고 주제를 바꿀 수 있었고 검증 시작 이후 새 콘솔 경고/오류가 없었다. 이번 회차에는 실제 PNG 다운로드나 메신저 전송을 하지 않았다.
- 기존 소유 리뷰 JPEG 5개(첫 화면·출생지 입력·오늘 결과·공유·PC 첫 화면)를 갱신해 보존했다. 로컬 fallback 테스트 서버와 최종 한국어 첫 화면을 유지했다.
- React 점검: 서비스에서 주제를 관리하고 컴포넌트에 전달한다. 타입별 UI 데이터 어댑터로 오늘과 기존 미리보기의 경계를 분리했다. 추가 데이터 요청·상태 동기화 effect·외부 라이브러리는 도입하지 않았다. 기존 effect 정리, native button/combobox/tab 접근성, 공유 object URL 정리를 유지한다.
