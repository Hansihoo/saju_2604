# Problem Definition 001

## 목적
- AI 사주 서비스 `suju-insight`가 어떤 문제를 해결하는지, 무엇을 핵심 가치로 삼는지 정의한다.
- 이후 사용 사례, 화면 구조, 정책 설계의 기준점이 되는 제품 원칙을 문서화한다.

## 이번 회차 목표
- 서비스의 본질을 "정확한 계산 기반의 설명 가능한 사주 해석"으로 명확히 정의한다.
- 계산 엔진과 LLM의 역할 경계를 확정한다.
- 구현 전에 먼저 닫아야 할 핵심 도메인 위험을 드러낸다.

## 문제 정의
- 기존 사주 서비스는 결과만 보여주거나 표현이 과장되는 경우가 많아, 사용자가 "왜 이런 해석이 나왔는지"를 신뢰하기 어렵다.
- 특히 생년월일, 생시, 지역에 따른 시간 보정이 부정확하면 이후 사주 계산, 만세력, 해석 전체가 흔들린다.
- 따라서 이 서비스는 "예쁘게 말하는 AI"보다 먼저 "정확한 계산과 검증 가능한 근거"를 제공해야 한다.

## 해결하려는 방식
- 입력값을 받아 시간 보정을 먼저 수행한다.
- 시간 보정 결과를 기반으로 사주팔자와 만세력 데이터를 생성한다.
- 정규화된 데이터 위에서 점수와 등급을 계산한다.
- LLM은 계산 결과와 판단 결과를 바탕으로 사용자 친화적인 문장과 구조로 설명한다.

## 제품 핵심 가치
- 정확성:
  - 시간 보정과 계산 정확도가 모든 경험의 출발점이다.
- 설명 가능성:
  - 사용자가 결과를 신뢰할 수 있도록 계산 근거와 해석 이유를 함께 제공한다.
- 절제된 표현:
  - 특별 등급이나 강조 표현은 실제 기준이 있을 때만 사용한다.
- 사용성:
  - 복잡한 사주 데이터를 단계적으로 공개해 초보 사용자도 읽을 수 있게 만든다.

## 핵심 원칙
- 팩트는 코드에서, 표현은 LLM에서.
- LLM은 판단하지 않는다.
- 점수와 등급은 분석 엔진이 산정한다.
- 잘 모르는 데이터를 과장해서 확정하지 않는다.
- 시간 보정 오류 가능성을 숨기지 않는다.

## 이번 단계에서 확정한 것
- 서비스는 웹에서 시작한다.
- 입력 기본안은 `생년월일`, `생시`, `성별`, `지역`이다.
- 생년월일은 양력/음력을 모두 지원하되 기본값은 양력이다.
- 생시는 시와 분을 모두 포함해 필수 입력으로 받는다.
- 출생시간 미상 사용자는 기본값 `00:00`으로 입력하되 시주 의존 결과는 제한한다.
- 시간 보정은 별도 핵심 모듈로 다룬다.
- 결과는 요약형에서 시작하고, 점차 상세한 설명으로 내려간다.
- MVP 1단계는 입력, 계산, 기본 해석까지다.
- 초기 서비스는 한국 기본값을 중심으로 설계한다.
- 첫 MVP는 비회원 1회 조회로 시작하고 결과 저장은 제외한다.
- 등급과 점수는 내부적으로 유지하되, 사용자에게는 요약된 표현 중심으로 보여준다.
- 오행, 십성, 대운 근거는 사용자가 원할 때 펼쳐보는 구조로 제공한다.

## 이번 단계에서 아직 미정인 것
- 누가 첫 핵심 사용자인가
- 한국 내수 중심으로 설계할지
- 장기적인 로그인 정책

## 왜 지금 이 문제가 중요한가
- 사주 서비스는 계산 오류가 곧 제품 신뢰 하락으로 이어진다.
- LLM을 전면에 세우면 표현은 좋아질 수 있어도, 근거 없는 해석이나 환각으로 신뢰를 잃을 수 있다.
- 따라서 제품 시작 단계에서부터 계산 정확성과 역할 분리를 원칙으로 잡아야 나중에 기능이 늘어도 흔들리지 않는다.

## 이번 회차 결정
- 제품의 차별화는 "AI 느낌"이 아니라 "정확한 계산 + 설명 가능한 해석"이다.
- 계산 엔진과 LLM의 역할을 명확히 분리한다.
- 시간 보정은 MVP에서 가장 먼저 검증해야 할 도메인 모듈이다.

## 남은 질문
- 첫 사용자는 사주 초보자인가, 반복 조회 사용자인가
- 첫 조회에서 어디까지 보여줄 것인가
- 신뢰를 위해 어떤 근거 정보를 노출할 것인가

## 다음 회차 시작점
- 대표 사용자 유형과 정상/실패 사용 시나리오를 정리한다.
