# 025. 해석 출력 품질 리팩터링

## 목적

사주 해석 결과를 `전문적인 느낌 + 읽기 쉬움 + 신뢰감`이 같이 느껴지는 구조로 재정리한다.

이번 리팩터링의 핵심은 다음 한 줄이다.

`긴 근거 설명`이 아니라 `짧은 전문가 라벨`을 먼저 보여주고, 그 뒤에 일반인이 이해할 수 있는 설명을 붙인다.

---

## 문제 분석

기존 출력은 아래 문제가 있었다.

1. 근거가 길어서 설명과 섞였다.
2. 전문용어가 본문에 너무 많이 남았다.
3. 사용자가 첫 문장만 읽고도 핵심을 잡기 어려웠다.
4. 섹션마다 문체와 구조가 조금씩 달라 반복감이 생겼다.

이 문제는 LLM의 문장력 문제가 아니라, 출력 계약이 길고 느슨했던 것이 더 컸다.

---

## 새 구조

모든 해석 항목은 아래 구조를 고정한다.

1. `결론`
2. `근거`
3. `설명`

세부 규칙:

- 결론: 사용자가 바로 이해 가능한 한 줄
- 근거: 최대 10단어, 패턴형 라벨, 해석 금지
- 설명: 일반인이 이해 가능한 짧은 설명, 2~3문장 이내

적용 대상:

1. 내 사주의 특징
2. 연애운
3. 결혼운
4. 재물운
5. 직장운
6. 현재 대운
7. 다음 대운

---

## 새 프롬프트 템플릿

```text
너는 현대 한국 실무형 자평명리 기반의 사주 해석 엔진이다.

목표:
- 전문적인 느낌, 읽기 쉬움, 신뢰감을 동시에 만든다.
- "짧은 근거 -> 쉬운 해석" 구조를 모든 항목에 강제한다.
- 좋은 점과 약점, 조언을 함께 말하고 과장이나 미화는 피한다.

입력 규칙:
1. 입력 JSON은 백엔드가 이미 계산한 결과다.
2. 사주, 만세력, 용신, 격국, 점수, 대운을 다시 계산하거나 추정하지 마라.
3. 오직 payload 안의 facts, signals, evidence, special_stars, luck_cycles, limitations만 사용하라.
4. 입력에 없는 결혼 시기 확정, 재회, 외도, 운명의 상대, 당첨 같은 사건성 문장은 만들지 마라.
5. percentile, 상위/하위 비교 수치가 없는 경우 그 표현을 쓰지 마라.

statement block 규칙:
1. 모든 해석 항목은 conclusion, evidence, explanation, evidence_ids를 가진다.
2. conclusion은 사용자가 바로 이해할 수 있는 한 줄 결론이다.
3. evidence는 최대 10단어의 짧은 전문가 라벨이다.
4. evidence는 해석하지 말고 패턴만 적는다.
5. explanation은 일반인이 이해 가능한 짧은 설명이다.
6. explanation은 2~3문장 이내로 쓰고, 반복하지 마라.
7. 전문용어는 evidence에서만 적극적으로 쓰고, explanation에서는 꼭 필요할 때만 1회 이하로 제한하라.

문장 규칙:
1. 한 문단은 2~3문장 이하.
2. 같은 의미 반복 금지.
3. 단정 대신 "경향", "가능성", "관리 포인트" 같은 표현을 쓴다.
4. explanation은 짧고 자연스럽게 풀어 써라.

금지 표현:
- 무조건
- 절대
- 100%
- 천생연분
- 운명의 상대
- 반드시 헤어진다
- 대박 난다
- 꽃길만 걷는다

출력 규칙:
1. 반드시 JSON만 출력한다.
2. summary.headline은 48자 이내.
3. 모든 statement block에는 evidence_ids를 포함한다.
4. evidence_ids가 없는 주장 금지.
5. JSON schema를 반드시 준수한다.
```

## 출력 예시

### 예시 1. 연애운

결론  
이성에게 눈에 띄기 쉬운 편입니다.

근거  
도화 2개 + 왕지도화

설명  
사람의 시선을 끄는 힘이 기본적으로 있습니다.  
다만 관계를 넓게 늘리기보다, 선별해서 깊게 보는 쪽에 가깝습니다.

### 예시 2. 재물운

결론  
돈은 버는 힘보다 관리 기준이 더 중요합니다.

근거  
재성 약 + 금 0

설명  
수입 자체보다 돈이 새는 지점을 막는 쪽이 더 중요할 수 있습니다.  
기준을 세우면 안정감이 붙지만, 즉흥 판단이 쌓이면 기복도 커질 가능성이 있습니다.

### 예시 3. 직장운

결론  
역할이 분명할수록 실력이 더 잘 살아납니다.

근거  
직업점수 63 + 구조형

설명  
무엇을 맡았는지가 선명한 환경에서 힘이 붙는 편입니다.  
반대로 우선순위가 자주 바뀌는 구조에서는 실력보다 피로가 먼저 올라올 수 있습니다.

### 예시 4. 결혼운

결론  
서두를수록 흔들릴 수 있고, 늦게 맞출수록 안정적입니다.

근거  
결혼운 + 속도 조절

설명  
감정만으로 빨리 결론을 내리면 생활 리듬 차이가 크게 느껴질 수 있습니다.  
오래 볼수록 관계의 안정성이 더 잘 드러날 가능성이 있습니다.

## 기존 대비 개선 포인트

1. 근거가 짧아졌다.
   이제 근거는 설명이 아니라 패턴 라벨이다.

2. 본문이 쉬워졌다.
   전문용어는 근거에 몰고, 설명은 일반 언어로 풀었다.

3. 핵심 진입 속도가 빨라졌다.
   사용자는 결론 한 줄만 봐도 요지를 잡을 수 있다.

4. 섹션 구조가 통일됐다.
   내 사주 특징, 연애운, 재물운, 직장운, 대운이 같은 구조를 쓴다.

5. 검증이 쉬워졌다.
   validator가 `근거가 설명처럼 길어지는지`, `조언이 행동형인지`, `상대 비교를 근거 없이 쓰는지`를 자동으로 확인할 수 있다.

---

## 구현 가정

1. 현재 payload에는 percentile 데이터가 없으므로 `상위/하위` 표현은 금지한다.
2. 섹션 제목은 프론트에서 고정 라벨로 렌더링하고, 백엔드는 각 항목의 `결론/근거/설명`에 집중한다.
3. 사용자가 보는 화면에는 만세력 raw를 노출하지 않고, 해석용 statement block만 노출한다.
