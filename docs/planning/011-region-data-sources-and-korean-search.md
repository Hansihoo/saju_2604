# Region Data Sources And Korean Search 011

## 목적
- 출생 지역 자동완성에서 한글 검색을 안정적으로 지원하기 위한 데이터 기준을 정리한다.
- 단순히 도시 이름을 많이 넣는 것이 아니라, 나중에 시간 보정과 좌표 보정까지 연결할 수 있는 소스를 남긴다.

## 현재 적용 방향
- MVP에서는 한국 주요 시 단위 지역 카탈로그를 정적 데이터로 관리한다.
- 각 지역은 최소한 아래 정보를 가진다.
  - `id`
  - `display_name`
  - `country`
  - `province`
  - `city`
  - `tzid`
  - `aliases`
- 검색은 `display_name`, `province`, `city`, `aliases`를 기준으로 수행한다.
- 한글 검색을 위해 아래 형태를 alias로 포함한다.
  - 시도 정식명
  - 시도 축약형
  - 시 이름
  - 시 접미사 제거형
  - `시도 + 시`
  - `축약형 시도 + 시`

## 왜 이렇게 하는가
- 한국 사용자는 `서울`, `서울시`, `서울특별시`, `경기 수원`, `수원시`처럼 입력한다.
- 따라서 단일 영문 도시명 매칭이나 단순 부분 검색만으로는 UX가 나빠진다.
- 또한 한국 MVP에서는 대부분 같은 `Asia/Seoul`을 쓰기 때문에, 자동완성 품질은 timezone보다 alias 품질이 더 중요하다.

## 공식 데이터 소스 후보

### 1. 행정표준코드관리시스템 법정동
- 용도: 공식 시도/시군구 명칭, 코드 기준 확보
- 활용 방식:
  - 정적 지역 테이블의 기준 명칭과 코드 소스로 사용
  - 추후 `adm_code` 필드 추가 시 기준 테이블로 사용

### 2. 주소정보누리집 검색 API
- 용도: 한국어 주소/지역 검색 UX 보강
- 활용 방식:
  - 사용자가 자유 입력한 텍스트를 검색 API로 보정
  - `admCd` 등 행정구역 정보를 받아 내부 지역 카탈로그와 매핑

### 3. SGIS 오픈API
- 용도: 좌표, 행정구역 단위 위치 정보 확보
- 활용 방식:
  - 나중에 `longitude`, `latitude`를 붙여 태양시 보정에 활용
  - 필요한 경우 좌표변환 API로 WGS84 좌표 체계 통일
