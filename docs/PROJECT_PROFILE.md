# PROJECT_PROFILE

## 목적
- 이 문서는 현재 `suju-insight` 프로젝트의 확정값, 기본값, 미정 항목을 한 곳에 모아두는 기준 문서다.
- 구현 전에 어떤 선택이 이미 끝났고, 어떤 질문이 아직 남아 있는지 빠르게 확인하기 위해 사용한다.

## 프로젝트 요약
- 프로젝트명: `suju-insight`
- 프로젝트 유형: AI 사주 해석 웹 서비스
- 제품 설명: 사용자가 생년월일, 생시, 성별, 지역을 입력하면 시간 보정과 사주 계산을 거친 뒤, 분석 엔진과 LLM 표현 레이어를 통해 개인 맞춤 해석을 제공한다.
- 핵심 원칙: 팩트는 코드에서, 표현은 LLM에서.
- 현재 결과 표현 방향: 앱형 대시보드보다 문서형 개인 풀이에 가깝게 읽히도록 구성한다.

## 현재 확정된 항목
- 서비스는 웹 기반으로 시작한다.
- 기본 시스템 흐름은 `Frontend -> API Server -> 시간 보정 -> 사주 계산 -> 만세력 생성 -> 정규화 데이터 -> 분석 엔진 -> LLM -> 결과 반환` 구조를 따른다.
- 입력 데이터 기본안은 `생년월일`, `생시`, `성별`, `지역`이다.
- 생년월일은 `양력/음력`을 모두 지원하되 기본값은 `양력`으로 둔다.
- 생시는 `HH:mm` 기준으로 시와 분을 모두 필수 입력으로 받는다.
- 출생시간을 모르는 경우에도 입력은 받되 기본값은 `00:00`으로 채운다.
- 출생시간이 기본값 `00:00`으로 들어간 경우, 시주 기반 만세력 정보와 시주 의존 해석은 결과에서 비활성화하거나 제한 표시한다.
- 시간 보정은 필수 핵심 모듈이며 `IANA 타임존`, `역사적 시간 변경`, `DST`를 반드시 고려한다.
- LLM은 판단 엔진이 아니라 표현 엔진으로 사용한다.
- 상용 기본 LLM provider는 `openai`로 둔다.
- 로컬 개인 테스트에서는 `SAJU_LLM_PROVIDER=codex`로 Codex CLI를 사용할 수 있다.
- OpenAI API 비용 없이 기능을 확인해야 할 때는 `SAJU_LLM_PROVIDER=fallback` 또는 `SAJU_LLM_PROVIDER=codex`를 사용한다.
- 점수와 등급 판단은 코드 기반 분석 엔진이 담당한다.
- 결과는 최소한 `요약`, `강점`, `약점`, `연애운`, `직업운`, `금전운`, `대운 흐름`, `행동 조언`을 포함한다.
- UX는 `요약 -> 상세 -> 설명`의 단계적 공개 구조를 기본으로 한다.
- 차별화 포인트는 `계산 근거 제공`, `해석 이유 제공`, `실제로 특별한 경우에만 강조`다.
- MVP 1단계 범위는 `입력`, `계산`, `기본 해석`이다.
- 초기 서비스는 `한국 기본값`을 중심으로 설계하고, 해외 지역 및 UI 다국어는 후속 단계로 미룬다.
- 첫 MVP는 `비회원 1회 조회`로 시작하며 결과 저장 기능은 포함하지 않는다.
- 사용자에게는 점수/등급의 원시값보다 요약된 표현을 우선 노출한다.
- 내부적으로는 점수/등급과 산출 근거를 명확하게 유지한다.
- 계산 근거는 `오행`, `십성`, `대운`까지 제공하되 기본 상태에서는 접어두고 사용자가 원할 때 펼쳐보는 구조로 설계한다.
- 지역 입력은 자유 텍스트 저장이 아니라 검색형 선택 UX를 사용한다.
- 사용자가 지역 입력창에 텍스트를 입력하면 연관 지역 후보를 아래 리스트로 제안하고, 사용자가 그중 하나를 선택하는 방식으로 설계한다.

## 현재 기본 기술안
- 저장소 구조: 단일 repo
- 프런트엔드 기본안: React + Vite
- 백엔드 기본안: FastAPI
- 데이터베이스 기본안: 아직 상용 저장 기능 미도입, 장기 후보는 PostgreSQL
- 배포 기본안: Vercel Services
- 웹 서비스 경로: `apps/web`, `/`에 mount
- API 서비스 경로: `apps/api/main.py`, `/api`에 mount
- 패키지 매니저 기본안: `pnpm`
- Python 도구 기본안: `uv`
- 문서 언어: 한국어

## 현재 구현 상태 요약
- 지역 검색, 시간 보정, 양력/음력 정규화, 사주/만세 계산 파이프라인을 구현했다.
- 출생시간 미상 정책과 시주 의존 결과 비활성화 정책을 구현했다.
- OpenAI API provider, 로컬 Codex CLI provider, deterministic fallback provider를 지원한다.
- 기본 provider는 `openai`이며, Codex provider는 개인 로컬 테스트 옵션이다.
- `/design-lab`은 저장된 fixture를 사용해 LLM 호출 없이 문서형 결과지 디자인을 비교한다.
- 실제 서비스 결과 화면은 에세이형 문서 레이아웃을 적용했다.
- 최근 UI 문구는 "핵심 카드" 같은 내부 용어보다 "먼저 읽어볼 부분" 같은 사용자 관점 표현으로 정리했다.

## 도메인 원칙
- 계산 정확도는 최우선 요구사항이다.
- 시간 보정이 틀리면 이후 계산과 해석 전체를 신뢰할 수 없으므로, 이 영역은 일반 기능보다 우선 검증한다.
- 특별 등급 시스템은 과장 마케팅이 아니라 실제 계산 결과와 기준이 있을 때만 부여한다.
- 해석 문장은 부드럽게 쓸 수 있지만, 근거 데이터와 모순되면 안 된다.
- 설명 가능한 해석을 목표로 한다.
- 입력값의 신뢰도가 낮으면 영향받는 결과 범위를 명확히 제한해야 한다.

## 분석 엔진 기본안
- 등급 체계:
  - `S`: 상위 5%
  - `A`: 상위 20%
  - `B`: 평균 이상
  - `C`: 일반
- 초기 판단 기준 후보:
  - 오행 불균형
  - 희귀 조합
  - 특정 기운 과다
- 초기 점수 항목 후보:
  - 매력 점수
  - 금전 점수
  - 직업 적합도
  - 리더십

## 이번 회차 결정
- 서비스 핵심을 "정확한 계산 + 설명 가능한 해석"으로 둔다.
- 시간 보정과 계산 로직은 제품 신뢰의 핵심이므로 MVP 초기부터 별도 검증 대상으로 취급한다.
- LLM은 표현만 담당하며, 판단 로직은 코드로 분리한다.
- 상용 기본값은 OpenAI API provider로 유지하고, Codex CLI provider는 로컬 개인 테스트 옵션으로만 사용한다.
- OpenAI API 없이 테스트할 때는 deterministic fallback 또는 Codex CLI provider를 사용한다.
- 양력/음력 입력을 모두 지원하고 기본값은 양력으로 둔다.
- 생시는 분 단위까지 필수 입력으로 받는다.
- 출생시간 미상 시 기본값 `00:00`으로 입력하되 시주 의존 결과는 비활성화한다.
- 한국을 초기 기본 지역으로 둔다.
- 첫 MVP는 비회원 1회 조회로 시작하고 저장 기능은 제외한다.
- 사용자에게는 요약형 결과를 우선 제공하고 내부 등급/산출 근거는 유지한다.
- 지역은 검색형 선택 UI로 입력받는다.
- 오행, 십성, 대운 근거는 접힌 상태로 제공하고 사용자가 펼쳐볼 수 있게 한다.
