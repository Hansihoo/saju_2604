# Product content knowledge

이 지식베이스는 이 프로젝트의 직접 사용자 피드백과 제품 편집 결정을 보존한다. 기계가 읽는 기준은 [PRODUCT_CONTENT_KNOWLEDGE.json](PRODUCT_CONTENT_KNOWLEDGE.json)이다. 명리 계산·해석 카탈로그에 사용자 선호를 사실이나 명리 규칙으로 넣지 않는다.

## 이번 문제와 재발 방지

| ID | 발생한 문제 | 다음 작업에서 지킬 기준 |
| --- | --- | --- |
| QF-001 | “연애할 때 난 어떤 타입?” 등으로 사주를 성격 테스트처럼 제안했다. | 주력 질문은 앞으로의 인연·취업·직장 변화와 시기다. 성격/연애 타입/일하는 스타일을 진입과 다음 질문의 흥미 장치로 되돌리지 않는다. 기존 성격 정보는 보조 결과에 유지할 수 있다. |
| QF-002 | 미지원 시기를 안내한 뒤 성향 풀이를 붙여 질문에 답한 것처럼 만들었다. | 질문을 유지하고 무엇이 부족한지 직접 설명한다. 기존 성향 본문·노트·조언·다음 질문으로 대신 답하지 않는다. 지원 한계 안내를 질문 만족이나 흥미 검증 통과로 기록하지 않는다. |
| QF-003 | 표현 변경으로 시기 정보를 제공한 것처럼 취급할 위험이 있었다. | 원하는 답 → 기간 사실 → 해석 규칙/예외/출처 검토 → 지원 조건 → 공개 순서로 보강한다. 제목만 미래형으로 바꾸지 않는다. |

이는 제품 소유자의 선호다. 모든 사람이 자기 성격을 알고 있다는 연구 결과나 사주의 사건 예측 정확도를 입증한 내용이 아니다. 사용자가 방향을 수정하면 새 피드백·버전을 기록한다.

첫 개발 목표는 “인연은 언제쯤 들어올까?”, “취업운은 언제쯤 풀릴까?”다. 두 질문은 아직 `needs_rule_review`이며 공개 기능으로 승격하지 않는다. 현재 진입은 오늘의 운세·연애운·직장/금전운·대운 흐름의 기존 주제를 사용한다. [038 계획](../planning/038-interest-led-reading-experience.md)과 [읽기 계약](SAJU_READING_AGENT.md)을 함께 따른다.

## 검증에 적용

- `scripts/verify-web-reading.cjs`가 JSON의 진입 정책을 읽어 실제 KO/EN `entryTopics`를 검사한다. 성격 topic의 재등장과 알려진 유형/스타일 질문을 실패로 처리한다. 거부 예시를 다시 넣는 변조 검사도 실행한다.
- 독립 역할 프롬프트는 QF-001~003과 정책 버전을 반영한다. 실행 시 실시간 문서·카탈로그를 읽지 않으며, 프롬프트/평가 버전을 올려 이전 작업의 재사용을 거부한다.
- 미지원 질문의 fixture 답변은 직접 한계와 필요한 자료 안내만 생성한다. 알려진 성향 답변·조언의 복사, 성향 본문·분석 노트·claim refs·다음 질문의 끼워 넣기는 코드 검사에서 FAIL이다. 감독의 긍정 평가로 상쇄하지 않는다.
- 사용자 역할은 “요청한 시기/사건 정보를 얻었는가”와 “지원 한계를 이해했는가”를 구별하고, 감독은 `question_fit`에서 성향 대체를 검토한다. 새 자연어의 의미는 자동 검사만으로 보장하지 않는다.

## 변경 절차

질문·진입·결과·추천·제품 계획 변경 전에 이 JSON과 문서를 읽는다. 신규 피드백에는 문제, 직접 출처, 적용 화면/역할, 결정, 예외, 검증 항목을 기록한다. `policy_version`은 계산 카탈로그의 knowledge/rule/copy 버전과 별개다. 의미 기준을 바꾸면 역할 prompt/rubric 버전도 갱신하고 오래된 작업을 새 작업으로 생성한다.

제품 선호와 전문가 규칙을 구별한 뒤 관련 회귀와 fallback-only 사용자 시나리오를 실행한다. 진행 상태와 남은 검토 범위를 `PROJECT_STATUS.md`와 `WORK_LOG.md`에 기록한다.
