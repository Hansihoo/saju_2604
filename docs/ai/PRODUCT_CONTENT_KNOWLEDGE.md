2026-10-09 최신 피드백: **“목차로 나눠서 관리해달라는게 아니야. 독자시점에 맞춰서 작성해줘.”** JSON의 독립 `distinctive_chart_reading`과 [054](../planning/054-reader-centered-distinctive-chart-reading.md)에 보존한다. 첫 본문은 이 명식에서 특히 눈에 띄는 특징과 그것이 뜻하는 복/부담, 크게 또는 제한적으로 작용하는 이유를 읽어주는 내용이어야 한다. 발견된 신살의 사전식 나열이나 성격 풀이를 개인별 종합 결론으로 취급하지 않는다. ‘더 궁금하면’은 이미 확인된 도화·태극귀인 등이 **내 사주에서 어떤 의미인지** 이어서 묻는다. 개인별 의미 답변을 지원하기 전에 기존 존재/위치 질문의 제목만 바꾸지 않는다. 최신 계약은 작성 목표를 보정하며 목차 기록과 runtime은 보존한다. 종합 규칙·질문별 의미 풀이·새 결과는 아직 구현되지 않았고053 효용 FAIL은 유지한다.

2026-10-09 [053](../planning/053-published-reading-and-folded-memos.md) 표시 구현: 제품 JSON publication_presentation.3 및 reading_outline_design.2를 먼저 읽는다. 실제 화면은 사주팔자 다음 다섯 장의 쉬운 본문, 해당 장 지원 질문, 기본 접힘 풀이 메모다. 어려운 명칭·위치·계산표 차이는 메모로 옮기되 주장 조건과 critical 보류는 숨기지 않는다. 전통 정의/계산 정보만 남는 장을 타고난 복이나 상용 콘텐츠 완성으로 승인하지 않는다. 종합·시기 규칙의 빈틈은 유지한다. 아래 기획 기록은 제안 당시 상태다.

2026-10-09 풀이 목차 요청: JSON의 독립 `reading_outline_design` (`fortune-reading-outline-2026-10-09.1`)과 [038의 작성 체계](../planning/038-interest-led-reading-experience.md#2026-10-09-풀이-목차와-작성-체계)를 따른다. 사주팔자를 맨 위에 두고 **내 사주의 특징 → 연애·결혼운 → 금전운 → 직장·직업운 → 지금부터 달라질 운**을 충분한 본문과 분류별 질문으로 연결한다. 개인별 결론부터 말하며 방법/용어/조언을 그 결론으로 대체하지 않는다. 도화 등은 확인된 경우 관련 장에만 설명한다. 질문 예시는 목표 답변이며 기존 미지원 시기·종합 길흉/강도 규칙의 공개 승인이 아니다. 목차/기획만 문서화했고 현재 런타임·역할 평가 버전은 유지한다.

2026-10-09 최신 실제 사용자 거절: “어떤 운을 타고 났고 어떤 불행을 타고 났다 어떤 흐름이 있다”, “내 성격 테스트 같은 심리 테스트 느낌”. 051의 환경별 장점·부담은 사용자가 원하는 사주 길흉 풀이를 대신하지 못했다. JSON `fortune_reading_feedback`에 원국의 분야별 복/불리한 구조 → 대운·세운의 도움/방해 → 결론과 반대 단서라는 요구를 독립 버전으로 보존한다. 성격·업무·학습 스타일과 일반 조언을 주력 결론으로 다시 만들지 않는다. 편집상 비중을 복이나 불운의 강도로 바꾸거나 제목만 운세형으로 고치지 않는다. 과거 좁은 에이전트 PASS는 삭제하지 않되 실제 사용자 만족으로 확대하지 않는다. 필요한 종합 판정 규칙은 아직 미구현이다.

2026-10-09 이전 요청: ‘내 사주의 특징’에서 좋은 점·나쁜 점을 각각 짚고 어느 정도 두드러지는지 설명한다. 사용자는 개인 명식에 맞춘 예외를 원하지 않고 **모든 사주에 적용하는 보편적인 구조와 접힌 추가 내용**을 명시했다. [051](../planning/051-general-chart-characteristics.md)과 JSON `characteristics_presentation`에 보존한다. 장점/부담/풀이 비중은 본문, 글자·전문 분류·계산 기준별 다른 풀이와 조건은 기본 접힘 메모로 제공한다. 같은 표시가 많다는 사실을 실제 능력/피해의 강도로 바꾸지 않는다. 긍정/부정이 모두 있으면 독립적으로 보여주며 ‘보통’으로 상쇄하거나 항상 양쪽을 억지로 채우지 않는다. 이 구현의 내용 방향은 위 최신 피드백으로 거절됐다.

2026-10-09 문체 요청: “재미있고 쉽게 풀이”, “사주가 나쁘면 나쁘다고”. JSON `reading_voice`와 [050](../planning/050-candid-and-playful-reading.md)에 직접 피드백을 보존한다. 기존 조건부 부담은 해당 조건과 불리한 점부터 말하며 “장점이지만/성장의 기회”를 자동으로 붙이지 않는다. 생활 비유는 짧고 의미에 맞게 사용한다. 실제 관계·직장 상태를 모르는 조건과 계산된 사실을 혼동하지 않는다. 발견된 불편한 전통 의미는 매력/재능으로 미화하지 않는다. 현재 종합 길흉 규칙이 없으므로 나쁜 사주라는 새 판정은 만들지 않는다. 판단할 수 없는 부분은 그대로 남긴다. 솔직한 말투·쉬운 설명과 개인별 종합 효용은 각각 검토한다.

2026-10-09 사용자 보강: 도화처럼 알려진 항목은 실제 확인됐을 때 위치와 쉬운 전통적 뜻을 본문에 설명하며, 없을 때는 자동 언급/빈 목록을 만들지 않는다. [049](../planning/049-present-signals-and-reading-information.md)와 JSON `present_signal_information`을 따른다. 말투만 늘리는 작업이 아니라 원본 명식·십성의 겉/안쪽 위치·신살 방법·대운 경계 정보를 공급한다. 계산은 만세력 엔진이고 Codex는 문장화한다. 용어·위치 정보의 증가와 개인별 종합 판단/미래 사건 질문의 해결을 구별한다. 첫 fallback의 일반 숙제·연애 상태를 전제하는 예시는 숨기고 실제 공급 사실을 먼저 표시한다. 조건이 불확실하면 분류마다 잠정 명식 정보를 표시한다.

이 지식베이스는 이 프로젝트의 직접 사용자 피드백과 제품 편집 결정을 보존한다. 기계가 읽는 기준은 [PRODUCT_CONTENT_KNOWLEDGE.json](PRODUCT_CONTENT_KNOWLEDGE.json)이다. 명리 계산·해석 카탈로그에 사용자 선호를 사실이나 명리 규칙으로 넣지 않는다.

## 이번 문제와 재발 방지

050 독립 답변자 검토는 원본의 화개 고독·공망 지연/약화·귀문관 집착이 쉬운 설명에서 사라진 점을 FAIL로 검출했다. 원본 엔진 사용 메타데이터를 대조해 복원했고 `reading_voice.adverse_meaning_preservation`에 보존한다. 부정적 뜻의 복원은 실제 성격·관계 실패·질환·전체 흉한 명식 판정과 구별한다. 원본 의미 누락을 말투의 친근함으로 덮지 않는다.

2026-10-09 실제 사용자 거절: “실질적으로 도움되는 말은 없고 어떻게 보여줄게라는 식의 내용이 다”는 **계산 방법 설명을 풀이로 착각한 문제**다. 쉬운 문장과 개인별 숫자가 등장해도 사용자에게 어떤 의미인지 결론이 없으면 기본 풀이의 효용은 FAIL이다. `basic_reading.py`가 모든 입력에서 vocabulary-only/해석 규칙 미적용을 명시한다는 원인을 확인했다. JSON `reading_content_review.utility_feedback`과 [047](../planning/047-reading-utility-recovery.md)을 따른다. 기존 r4 기술/역할 PASS는 역사로 보존하며 풀이 완성 상태를 다시 연다. 검증 계약을 고친 것이 실제 종합 풀이/시기 판정을 구현한 것은 아니다.

2026-10-08 최신 본문 보정: “너무 어렵게 써서 뭔소리인지 모르겠어”라는 피드백은 용어 설명을 읽기 좋은 풀이로 착각한 문제다. JSON의 독립 `reading_presentation`과 [046](../planning/046-plain-reading-and-folded-evidence.md)에 보존했다. 쉬운 본문을 먼저 보여주고 한자·십성·정밀 날짜·오행 개수·판정 방법은 작은 기본 접힘 **풀이 메모**로 모은다. 근거를 펼쳐야 본문 뜻을 알 수 있게 작성하지 않는다. 같은 분류의 일반 설명을 여러 카드에서 반복하지 않는다. 시간 미상·날짜 기준의 실제 한계는 밖에 남기며 일주를 확정한 것처럼 쓰지 않는다. 이 표시 개선으로 미지원 미래 질문이나 실제 사용자 흥미가 검증됐다고 주장하지 않는다.

## 전체 풀이가 밋밋해진 원인 검토

2026-10-07 사용자는 **모든 항목**이 재미없고 초기 내용이 더 유익했다고 지적했다. 연애 상황만의 문제나 말투 문제로 축소하지 않는다. JSON의 독립 `reading_content_review`에 피드백과 소스 비교를 보존했다. 상태는 **원인 확인, 런타임 복구 미구현**이다. 실행 정책/역할 평가 버전은 변경하지 않았다.

`03075d9`의 초기 무료 풀이와 `8fd02a6`의 고도화 prompt는 일·수입 구조·지출 관리와 현재/다음 대운을 함께 다루도록 했다. `53f736e`에서 도입한 지식 계약은 주제별 한 feature/규칙에 주요 해석 범위를 묶고 `scene → tradeoff → action` 세 문단을 우선한다. 현재 직장/금전은 월간 십성, 연애는 배우자궁 십성, 대운은 현재 대운 천간 십성이 주요 선택 기준이다. 사실 payload에 있는 다른 정보를 모두 없앤 것은 아니지만 주요 결론에 쓰는 폭이 줄었다.

특히 [generate_free_preview.py](../../apps/api/app/domain/saju/services/generate_free_preview.py)의 fallback은 `_fact_aware_cards` 뒤에 `apply_reading_plan`을 호출한다. [build_reading_plan.py](../../apps/api/app/domain/saju/services/build_reading_plan.py)는 기존 카드의 제목·핵심 문장·본문·다음 질문을 카탈로그 문장으로 덮어쓴다. 모델 결과는 이 덮어쓰기와 같은 경로가 아니지만 [free_preview_report.py](../../apps/api/app/domain/saju/prompts/free_preview_report.py)의 우선 지시로 같은 질문/규칙 범위를 지키고 다른 결론을 추가하지 못하게 한다. 반복적인 생활 예시·주의·행동 과제가 실제 사주 설명을 대신하게 된 원인이다.

주 화면의 전체 개요가 core에만 있고 `core_diagnoses`가 표시되지 않는 것도 확인했다. 핵심 정보와 전문 근거 설명은 구별해야 한다. **지원 가능한 개인별 핵심 설명은 본문**, 세부 용어·계산 설명은 기본 접힘 **풀이 메모**에 둔다. 메모를 작게 두라는 사용자 요청을 정보 자체를 줄이라는 요청으로 해석하지 않는다.

회복 방향은 초기 정보 범위를 검토해 되살리는 것이다. 말투만 자극적으로 바꾸거나 모든 주제에 같은 예시/주의/숙제를 붙이지 않는다. 일·수입·지출의 구별, 현재와 다음 대운의 계산된 기간/해석 차이, 연애 상황별 적합한 설명을 각각 검토한다. 기존 성격/타입 진입 금지, 미지원 미래 질문의 성향 대체 금지와 근거·불확실성 경계는 유지한다. 초기 규칙/문구를 무검토로 복원하거나 확률·순위·임의 점수를 내보내는 결정은 아니다.

비교는 저장소 소스 기준이다. 사용자의 초기 결과 원문을 특정하거나 같은 출생정보로 전후 결과를 재생성하지 않았으며 초기 해석의 정확도도 입증하지 않았다. 구조·출처 일치 테스트 통과는 유익함/흥미 통과가 아니다. 복구 때는 같은 입력의 전후 출력과 주제별 정보 범위·조언 반복·질문 적합성을 별도로 비교한다. 이번 검토는 모델/API 호출이나 런타임 변경 없이 수행했다.

2026-10-08 시기 답변 보정: 사용자는 “대운에 재성이 있다”를 설명한 뒤 “만남 시기는 별도 검토가 필요하다”로 끝나는 초안에 **“그럼 왜 알려주는거야?”**라고 지적했다. 원하는 답은 같은 사람의 기간을 비교했을 때 연인을 만날 기회가 높아진다고 읽는 시기다. 10년 대운은 배경 자료이며 만남의 유리한 시기를 답한 것이 아니다. 긴 명식 설명이나 한계 문장을 흥미/질문 충족으로 기록하지 않는다. JSON `reading_content_review`의 독립 검토 버전을 갱신했다.

지원된 시기 질문의 내용 순서는 **주목할 시기 → 다른 기간과 구별되는 이유 → 반대 단서와 해석 한계 → 맥락에 맞는 행동**이다. 기간/규칙이 없으면 첫 답을 만들어 채우지 않는다. 현재 `love.meeting_window`는 `needs_rule_review`이며 기존 월운의 일반 참고 규칙이나 대운 `favorable_periods` 휴리스틱은 만남 시기 선정 규칙이 아니다. 이 피드백은 판정 기능의 우선순위를 명확히 한 것이고 런타임/역할 기준 변경 또는 날짜 추천 구현은 아니다. 시기 정보를 구현할 때 실제 사건 확률과 전통 해석상 기간 비교를 구별하며, 미지원 상태를 메모에 숨기거나 지표 명칭만 바꿔 공개하지 않는다. 자세한 답변 요구는 [042](../planning/042-context-aware-love-readings.md)를 따른다.

2026-10-08 정보/흥미 정리 요청: JSON의 독립 `information_design`과 [038 통합 정리](../planning/038-interest-led-reading-experience.md#2026-10-08-정보와-흥미-설계-정리)에 보여줄 정보, 읽는 순서, 상황별 질문, 충분한 본문과 작은 메모, 지수/공유/재방문, 검증 가설을 묶었다. 첫 진입 단일화와 성격/타입 훅 금지는 유지한다. 핵심은 지원된 미래/기간 답과 개인별 근거이며 캐릭터·분량·고정 세 문단을 정보의 대용으로 쓰지 않는다. 문구 분량은 목표 정보에 맞춰 조정하고 새 출력 형식은 별도 계약/버전/호환 검토를 거쳐야 한다. 이 정리는 planning 상태이며 시기/맥락/지수/공유의 런타임 지원이나 역할 판정 변경이 아니다.

같은 날 기본 사주 후 질문 선택 제안: `information_design`의 독립 버전을 갱신하고 `question_reading_flow`에 계산된 기본 사주→지원 질문→필요한 상황→질문별 판정/풀이→다음 질문/공유를 기록했다. 계산만 하는 경로와 준비/문장화/cache 분리는 현재 코드에 존재한다. 질문 ID·상황·질문별 규칙/응답은 후속 구현이다. 기존3개 상세 유형을 모든 질문의 지원으로 취급하지 않으며 미지원 시기 질문을 이름만 바꿔 공개하지 않는다. 현재 runtime의 단일 CTA/today 기본 결과는 변경하지 않았다. 최초 기본 사실은 모든 질문의 LLM 결과를 기다리지 않는 방향으로 설계하되 실제 속도/비용 감소는 아직 측정하지 않았다.

## 검증에 적용

2026-10-07 연애 맥락 피드백: 사용자는 연인이 없고 만남을 원했지만 “서로에게 관심을 표현하고 각자의 시간을 존중하라”는 관계 조언을 받았다. 상황을 받지 않고 관계 성향을 연애운 전체의 답으로 사용한 문제다. 먼저 `새 인연을 만나고 싶어`와 `지금 연애 중이야`의 원하는 답을 구분한다. 솔로에게 커플 대화·약속·서운함을 직접 답으로 대신 주지 않는다. 교제 중인 사람의 실제 상대 감정·관계 결과도 본인 사주로 확정하지 않는다. 상태 미응답은 추측하지 않는다. QF-002의 성향 대체 금지는 계속 적용한다. 새 runtime 계약/의미 판정 기준을 구현할 때 관련 버전을 함께 올린다.

질문·진입·결과·추천·제품 계획 변경 전에 이 JSON과 문서를 읽는다. 신규 피드백에는 문제, 직접 출처, 적용 화면/역할, 결정, 예외, 검증 항목을 기록한다. `policy_version`은 계산 카탈로그의 knowledge/rule/copy 버전과 별개다. 의미 기준을 바꾸면 역할 prompt/rubric 버전도 갱신하고 오래된 작업을 새 작업으로 생성한다.

# 초기 전체 풀이와 분류별 질문 (2026-10-09)

최신 요청은 기존 장문 풀이를 내 사주의 특징·연애/결혼·금전·직장/직업·현재/다음 대운 순서로 먼저 보여주고, 관련 지원 질문을 각 분류 아래에 붙이는 것이다. JSON `category_reading_presentation`과 [048](../planning/048-category-reading-and-questions.md)을 따른다. 초기 전체 보고서는 한 번만 생성하고 전문 설명은 분류별 기본 접힘 메모, 선택 질문은 해당 답만 요청한다. 기존 `/saju/basic`의 계산 사실 계약은 호환용으로 유지한다.

기존 보고서 연결만으로 유익함 회복을 완료했다고 기록하지 않는다. fallback에는 단일 feature 예시/조언과 금전 일반 장문이 남아 있으므로 독립 의미 검토가 필요하다. critical 전체 보류·새 인연/취업 시기 미지원·성향 대체 금지는 계속 적용한다.
