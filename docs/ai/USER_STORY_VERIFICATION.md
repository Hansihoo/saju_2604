# 사용자 시나리오 독립 검증

2026-10-04 KST. 기존 프로젝트의 모바일 진입 → 주제 선택 → 출생 정보/출생지 → 실제 결과 → 전체 풀이 → 공유 카드 흐름을 검증한다. 계산 기준은 기존 legacy를 유지한다. 현재 거주지는 수집하지 않는다.

## 검증 역할과 범위

| 담당 | 독립 확인 범위 | 상태 |
| --- | --- | --- |
| 루트 | 실제 Chrome UI, 모바일/PC, API 연결, 전체 풀이, PNG 생성, 오류/불확실성 전달 | Done |
| information_review | 출생지 보정·시간 미상 제한·계산 근거·문장 개인화·잘못된 시기 단정 | Done |
| ux_review | 쉬운 접근, 질문/결과 부합, 흥미, 말투, 공유 이유 | Done |
| verification_system | 별도 stdlib HTTP 검증기, 합성 사례·입력 오류·반복성·근거·개인화 비교 | Done |

에이전트 평가는 실제 사용자의 재미/공유 의향 측정과 구분한다. 계산 구현·기준값 회귀 검증을 현실의 미래 예측 정확도로 확대하지 않는다. 현재 런타임 검증은 fallback 모드다. OpenAI/Codex의 실제 생성 문장을 검증했다고 주장하지 않는다.

## 발견 사항과 처리

| 발견 | 영향 | 처리 |
| --- | --- | --- |
| 서로 다른 명식에도 연애·일/돈 fallback 카드가 완전히 동일 | 질문/공유 카드가 개인별 정보처럼 보이지만 일반론을 반복 | 계산된 배우자궁/월간 십성 범주와 제공된 분포에 따라 제목·본문·한마디를 변경. 근거 라벨과 연결. 새로운 점수·예측 공식은 추가하지 않음. |

| 실제 음력 1990-02-30을 API가 422로 거절 | 기준표상 존재하는 생일을 입력할 수 없음 | **Needs review**. KASI 변환 표에서 양력 1990-03-26에 대응함을 확인. birth_date:date가 양력 검증을 적용하는 기존 입력 계약 결함. 공개 입력 처리 변경에 대한 사용자 답변 대기. 검증기에서 실제 FAIL로 기록. |
| live LLM validator가 상대 감정 단정을 차단하지 못함 | 계산에 없는 문장이 생성돼도 형식 검증을 통과할 수 있음 | **Needs review**. 변조된 '상대방도 당신을 좋아하고 곧 연락할 가능성이 아주 높습니다.'가 validator를 통과함을 독립 확인. 개선 fallback은 이 문장을 생성하지 않지만 실제 LLM 사실 검증은 별도 보강 필요. |

## 사용자 관점 재검토

독립 UX 검토에서 설명서식 제목을 생활 속 질문으로 바꾼 점, 네 주제 선택과 두 단계 입력, 캐릭터 및 한마디 카드가 개선된 것으로 평가됐다.

실제 서로 다른 합성 명식에서 다음과 같이 달라졌다.

| 주제 | 서울 사례 | 부산 사례 |
| --- | --- | --- |
| 연애 | 좋아해도 내 시간은 지키고 싶은 걸까? | 마음이 편해야 가까워지는 걸까? |
| 일/돈 | 일은 돌아가는데 왜 내 일정은 꽉 찰까? | 같이 일하는데 왜 내 몫만 늘어날까? |

이는 제공된 사실을 기존 범주로 문장화한 결과다. 같은 범주의 사용자가 같은 문장을 받을 수 있다. 각 사람에게 유일한 진단이라고 홍보하지 않는다. 확대 문장의 반복 한계 설명과 상단 중복 경고는 재검토 지적에 따라 줄였다. 영어 미상 풀이에 남은 다음 대운 준비 문구도 시간과 무관한 생활 장면으로 바꿨다. KO/EN 사용자 제한 문구에서 내부 placeholder 시각은 제외하고 실제 계산 응답의 구조화된 상태는 유지했다.

## 후속 결과 콘텐츠 감사

사용자의 “결과 정보가 재미있고 의미있고 전문성 있는지” 요청에 따라 루트와 UX/정보 에이전트가 다시 읽기 전용으로 검토했다. 정지된 기존 관리 API만 fallback으로 복구했다. 서울·부산·시간 미상 세 합성 사례의 실제 preview와 상세를 비교했으며 정보 에이전트의 6건은 모두 HTTP200이다. 매 POST 전에 서버 fallback 확인 및 보호 헤더를 사용했다. 외부 LLM 호출·계산식·제품 코드 변경은 없었다.

판단: **생활에서 써볼 만한 조언은 있지만, 충분히 재미있고 개인별 해석을 납득시킬 수 있는 결과 콘텐츠로는 아직 부족하다.** 앞선 기능 회귀 통과는 이 콘텐츠의 품질 승인이나 문장별 추론 검증을 뜻하지 않는다.

| 기준 | 좋은 점 | 남은 약점 |
| --- | --- | --- |
| 재미 | “일은 돌아가는데 왜 내 일정은 꽉 찰까?” 등 생활 장면이 떠오르는 제목 | 질문 뒤 직접적인 해석보다 점검 지시가 많음. 입구의 “말해줄게”와 본문의 “살펴볼 만합니다/편이 좋습니다”가 다른 목소리이며, 공유 한마디도 정중한 조언 위주. |
| 의미 | “믿고 맡긴다는 말이 내 일정 전체를 뜻하지는 않습니다.”처럼 책임 범위와 직접 대화를 점검하는 조언 | 서울·부산 연애 3/4문단 및 일·돈 3/4문단이 동일. 펼친 뒤 새로운 개인별 정보가 적음. “관계 정리…작은 행동 하나로 줄여보세요”는 무엇을 할지 다시 사용자에게 맡김. |
| 전문성 | 계산된 월간/배우자궁 십성 범주로 첫 문장을 선택하고 시간 미상 제한을 명시 | 아래의 상세 결론 중복·해석 일관성·문장 근거 연결 문제를 해결해야 함. 카드의 basis_line은 API에 있어도 현재 카드 UI에는 표시되지 않음. |

확인한 내용 결함과 우선순위:

1. **우선: 요약과 상세의 개인별 해석을 일치시킨다.** 다른 명식인 서울·부산의 상세 연애/직장/금전 “핵심 결론”이 동일했다. 성격 preview는 토를 안정적 정리, 화를 빠른 반응/표현으로 구분하지만 상세는 둘 다 “빠른 반응과 정리력”이라고 쓴다. 단어와 개수만 바꾸는 상세 확장을 개인별 깊은 해석으로 취급하지 않는다.
2. **우선: 문장에 사용한 근거가 실제로 연결되는지 검증한다.** 서울 상세 연애는 왕지도화·역마를 언급하지만 연결 ID에는 역마가 빠졌다. 시간 미상 상세 금전은 월간/십성 수치를 인용하면서 연결 근거는 elements뿐이다. 존재하는 근거 ID 목록을 검사하는 것과 문장에 사용한 모든 사실을 추적하는 것은 다르다. 미상 career/wealth는 전체 본문도 동일했다.
3. **다음: 내용을 채우는 기준을 길이에서 정보 역할로 바꾼다.** 현재 생성 검증은 카드 최소 480자·최소 3문단, hero 최소 7문장을 요구하고 repair는 카드 4문단×190~260자 확장을 지시한다. 이러한 기준은 모바일에서 짧게 읽고 공유하려는 목적과 충돌할 수 있다. 원인이라는 판단은 구현을 읽은 기술적 해석이며, 분량 변경 효과는 사용자 테스트로 확인해야 한다.
4. **다음: 친근한 말투와 작은 근거 확인 경로를 정돈한다.** 한 줄 해석 → 생활 장면 → 한 가지 행동을 먼저 제시하고, “왜 이렇게 읽었어?”에서 확인한 단서와 해석 방향을 연결한다. 전문 용어 전체를 메인에 펼치지 않는다. “목를/금를” 조사 오류와 미상 카드의 “다음 변화” chip/question도 정돈 대상이다. 미상 KO 후반 문단은 일반 점검 조언이며 미래 시기를 확정한 문장으로 오판하지 않는다.

검증 전 편집 예시(서울 연애 범주):

> 연애에서도, 내 하루는 남겨 둬야 편할 수 있어.
> 함께하는 시간만큼 혼자 쉬는 시간도 맞춰보자는 풀이야.
> 다음 약속 잡을 때, 각자 쉬는 날도 하나씩 이야기해봐.

접은 근거에는 “배우자궁 겁재를 확인해 관계 속 내 기준과 시간 배분을 먼저 살펴봤어”처럼 확인한 사실과 선택한 해석을 구분한다. 생활 장면은 예시이고 사용자의 실제 경험으로 단정하지 않는다. 이 문구와 적정 길이는 구현·사용자 실험 전 제안이다.

후속 품질 검증은 서로 다른 계산 범주의 결과 비교, 요약/상세 결론 일치, 새 정보 없는 중복 문단, 문장별 사용 사실과 근거의 대응, 시간 미상 전 화면/카드 제한 일치를 포함해야 한다. 실제 사용자에게는 재미 점수의 근거 없이 백분율을 부여하지 않고 “기억에 남는 한 문장”, “나를 설명하는 부분”, “공유하고 싶은 이유”를 직접 확인한다. 이번에는 그러한 사람 대상 검증이나 실제 LLM 생성 문장 검증을 수행하지 않았다.

## 전체 표시와 전문가 분석 노트

최신 사용자 요청에 따라 메인 주제의 본문·칩·성격 요약과 분석 노트를 모두 항상 표시한다. 본문 말줄임과 `이어서 읽기`, 요약 접기, `왜 이렇게 읽었어?` 버튼을 제거했다. 주제별 모든 본문 문단을 렌더하며 성격 요약은 실제 응답의 8개 문단을 확인했다. 계산식·명식·입력 계약·LLM 요청 계약은 유지한다. 명시적인 전체 상세 API 호출과 보조 기간/참고사항은 기존 별도 기능으로 유지한다.

조언에는 기기 기본 명조 계열(Batang/AppleMyungjo/serif)을 적용했다. 모바일 16px, PC 17px로 본문의 고딕 14/15px과 구분하며 새 외부 폰트 다운로드는 추가하지 않는다. 작은 `분석 노트` 제목(11px) 아래 **명식 근거 → 해석 기준**을 12px로 표시한다. 이미 강조된 조언을 노트에서 다시 반복하지 않는다. 분석 노트는 정적 aside이며 토글·숨김 상태가 없다. 실제 서버의 단서만 사용하고 이전/다른 provider 응답에는 제공된 근거만 표시한다.

실제 서울 사례의 노트는 “월간 십성은 ‘편관’입니다. 이를 근거로 책임의 범위와 마감 관리에 관한 해석 방향을 검토했습니다.” 및 “배우자궁에서 확인된 십성은 ‘겁재’입니다. 이를 근거로 관계 안에서의 개인 기준과 시간 배분에 관한 해석 방향을 검토했습니다.”다. 표면 오행·일간과 일진/절기 월주 천간·대운을 기존 계산 단서에 연결한다. 시간 미상에서는 시주 제외, 시기 비교 보류와 시간 민감한 연결 제외를 유지한다. 명식의 계산 사실과 해석 관점을 구분하며 미래 사건의 정확도나 확정 예측을 주장하지 않는다.

독립 정보 에이전트의 API 전체 **305개**, 마지막 사실형 문구 정돈 후 관련 **84개**가 통과했다. 영어 미상 표현을 `unknown birth time`으로 명확히 정돈한 뒤 기간/검증기 **41개**를 다시 통과했다. 첫 실제 HTTP 실행의 영어 미상 2건 실패는 검증기의 고정 구절과 동의어 문장이 다른 데서 발생했으며, 검증 규칙을 약화하지 않고 본문 표현을 정돈했다. 최종 HTTP는 **238 PASS / 2 WARN / 1 FAIL**로 기존 음력 2월 30일 입력 422만 기능 실패다. 실제 사용자 흥미·live LLM 의미 정확도 WARN은 남긴다. 모든 요청은 fallback 확인/보호 아래 실행했고 외부 생성 호출은 없다.

웹 타입 검사와 production build, 기존 helper **10개**, diff 검사를 통과했다. 루트는 실제 앱 내 브라우저에서 KO known·EN unknown, 다섯 주제의 전체 문단/요약·분석 노트, 320/390/1440px의 작은 노트와 명조 강조를 확인했다. 주제별 말줄임은 0개이고 최종 감사 상태는 `pass`였다. 독립 UX 에이전트는 서울·부산·미상·EN서울 4개의 실제 guarded 응답에서 전문 문체와 사실/해석 분리를 확인했으며 필수 수정 사항은 없었다. 기존 본문 반복·긴 분량과 전체 상세의 개인화 문제는 별도 검토로 남긴다.

영문 모바일 탭의 `Personality` 단어가 고정된 칸보다 넓어 자동 감사 경고가 발생함을 DOM 너비로 확인했다. 탭에 긴 단어 줄바꿈을 적용하고 production build를 재통과했다. 변경 후 320/390px의 전체 주제와 새 영어 미상 응답을 확인했다. 320px 오늘 화면에서 다섯 탭 모두 `scrollWidth = clientWidth = 54`, 감사 `pass`/0개였다. 초기 경고를 삭제하거나 세션 전체에 경고가 없었다고 주장하지 않는다.

## 이전 접기 버전의 구현·검증

다섯 주제의 메인 결과 카드에 `왜 이렇게 읽었어?`를 추가했다. 기본으로 접히며 `근거 숨기기`로 다시 닫는다. 닫혀 있을 때 근거 본문은 렌더하지 않는다. 주제·새 결과가 바뀌면 접히고 `이어서 읽기`와 상태를 분리한다. 입력·출생지 보정·계산식·긴 상세의 분량 규칙은 유지했다.

펼치면 **확인한 단서 → 쉽게 풀면 → 그래서 나온 조언**을 보여준다. 서울 연애의 실제 연결은 `배우자궁 겁재 → 관계 속 내 기준과 시간 배분 → 함께하는 시간과 혼자 쉬는 시간 맞추기`다. 일은 `월간 편관 → 책임과 마감 범위 → 추가 업무의 일정·담당 범위 조정`이다. 독립 UX 검토에서 친근한 말투와 연결을 확인했으며 필수 수정은 없었다. 권고에 따라 동일한 현재·다음 대운 분류는 “두 구간 모두 …라는 주제로 읽었어”로 축약했고 `목를/금를` 조사 오류도 수정했다.

API 카드와 기간 흐름에 선택 필드 `basis_explanation: {facts, reading}`을 추가했다. facts는 1~3개×96자, reading은 360자 이내다. fallback의 실제 계산 payload에서 단서를 만들고 기존 조언을 연결한다. 기존 LLM 요청의 8개 카드 필드는 유지하며 모델이 임의로 보낸 설명은 채택하지 않는다. 이전 응답·live-generated 본문은 기존 `basis_line`을 **풀이에 적힌 단서**로만 표시하고 프론트에서 해석을 만들어 붙이지 않는다. 실제 LLM 문장의 의미 검증은 별도 과제다.

미상 결과는 시주·대운 계산 비활성과 시점 판단 보류를 설명한다. 오늘도 시주·대운 연결 제외를 명시하며 중요한 날짜 경계·미상 안내는 접힌 근거 밖에서 유지한다. 오늘·이번 달은 기존 날짜/간지·일간·십성·지지 관계를 기존 period-flow 조언과 연결한다. 이번 달은 API 데이터 검증에 포함됐으며 UI 주제는 기존 다섯 개를 유지했다.

최신 HTTP 결과는 **238 PASS / 2 WARN / 1 FAIL**이다. 새 근거 검사 100개가 통과했다. 기존 `known_issue.valid_lunar_day30` 입력 422는 FAIL로 유지한다. WARN은 실사용자 흥미와 live LLM 의미 정확도다. fallback 확인·요청 보호·응답 진단을 거쳤고 외부 생성 호출은 없었다. 확인된 근거 일치 범위를 미래 예측 정확도로 확대하지 않는다.

브라우저 앱 오류는 없었다. 검증 중 자동 넘침 감사 경고가 4건 기록됐다. 이후 최종 320px에서 오늘을 포함한 다섯 주제의 열린 근거를 다시 확인해 감사 상태 `pass`, 항목 0개를 확인했다. 페이지 폭을 넘는 요소도 없었다. 경고를 삭제하거나 전체 세션에 경고가 없었다고 주장하지 않으며, 화면·폭 전환 중의 재현 추적 대상으로 기록한다.

긴 상세의 공통 결론·요약/상세 성격 표현 차이·문장별 근거 ID 연결, 분량 중심 규칙은 별도 `Needs review`로 남긴다. 실제 사용자 재미/공유 의향 측정은 수행하지 않았다. 검토 자료와 fallback 테스트 환경을 유지한다.

## 반복 실행

API 8000 / 웹 5173이 실행 중이어야 한다. 테스트용 API는 `SAJU_LLM_PROVIDER=fallback`으로 시작한다. 실행기는 서버의 provider를 직접 확인하고, 각 POST의 fallback guard와 응답 진단도 확인한다. 서버 환경을 바꾸거나 외부 LLM을 호출하지 않는다.

```powershell
pnpm verify:user-story
pnpm verify:user-story -AllApiTests
```

`-SkipBuild -SkipTests`는 이미 통과한 빌드/회귀를 반복하지 않고 HTTP 런타임만 검사한다. `-ApiBase`, `-WebBase`, `-Output`으로 대상과 출력 경로를 지정할 수 있다. 기본 보고서는 [USER_STORY_VERIFICATION.json](USER_STORY_VERIFICATION.json)이다.

별도 검증기는 KO 5개와 EN 미상 1개의 합성 사례, 유효/무효 입력, 실제 오늘 날짜·출생지 시간대·절기 월 기간, legacy 유지·반복 결정성, 4개 카드와 근거, 상세 연결, 다른 명식의 연애/일·돈 완전 동일 여부를 검사한다. 미상 preview/상세의 확인된 잘못된 시기 단정은 좁은 회귀 패턴으로 검사하며 모든 의미를 검증했다고 주장하지 않는다. 상태를 기능/내용/사람 검토 범주로 나눈다. 확인된 결함은 FAIL, 의미 검토가 필요한 근거와 실제 사용자 흥미는 WARN이다. 실패나 provider 확인 불가 시 0이 아닌 종료 코드를 반환한다.

웹 보조 검증은 기존 TypeScript 컴파일러로 실제 날짜·오류 번역·중요 불확실성·공유 제한 helper를 검사한다. 빌드는 타입 검사와 Vite production build를 포함한다. 브라우저 흐름은 HTTP 검증기와 별도로 사람이 확인해야 한다.

## 2026-10-05 질문·지식·읽기 계약 보강

사용자 요청에 따라 말투와 판정을 분리했다. 루트 `AGENTS.md`는 [SAJU_READING_AGENT.md](SAJU_READING_AGENT.md)를 필수 작업 문서로 연결한다. 출처·feature/value·제외 조건·허용 claim·규칙/지식/문구 버전·KO/EN 표현은 엄격한 JSON 카탈로그에서 관리한다. 현재 21개 규칙은 기존 프로젝트 정책이며 전문가 검증 완료나 실제 사건 예측 정확도로 소개하지 않는다.

네 메인 fallback 주제는 **질문 → 핵심 답 → 생활 예시 → 함께 볼 부담 → 행동 → 분석 노트**를 따른다. 각 문장에 규칙/사실 ID와 실제 payload 경로를 연결한다. `analysis_note`도 같은 규칙과 사실로 만들고 `basis_explanation/basis_line` 및 상세 성격·연애·직장·현재 대운에 적용한다. 본문과 노트를 함께 변조하거나 다른 규칙의 노트를 복사해도 원 payload/카탈로그와 대조해 실패한다. 성격의 화면/공유 제목은 선택된 동일 질문이며 공유 강조 문장도 동일한 답이다. 모든 메인 문장과 작은 정적 분석 노트, 명조 강조는 유지한다.

독립 검토가 발견한 성격의 오행 부족 설명 혼합과 대운의 다음 구간 설명 혼합은 수정했다. 실제 부산 HTTP에서 오늘 노트 누락도 발견했다. 라이브러리 표기 `七杀`가 편관으로 정규화되지 않아 peer 규칙으로 잘못 분류될 수 있던 원인을 고쳤다. `七杀/七殺/偏官→편관`을 사용하며 알 수 없는 기간 십성/천간 조합을 임의의 peer/일간으로 대체하지 않는다. 100개 실제 라이브러리 천간 관계와 KO/EN 편관 규칙·노트를 회귀에 포함했다.

HTTP WARN은 `quality.unobservable_luck_ten_god`, `quality.real_user_interest`, `quality.live_llm_semantic_accuracy`다. 대운 천간 십성은 공개 raw 계산 응답에 없으므로 독립 HTTP 검사에서 실제값 검증 PASS로 세지 않는다. 경로/선택 규칙/표현 정합성 확인과 내부 supplied-payload 회귀를 구별한다. 외부 LLM 호출은 하지 않았고 생성된 문구의 의미 전체나 실제 흥미를 검증했다고 주장하지 않는다.

만남·취업·인정·보상 시기와 타인 운 비교 5질문에는 부족한 요구사항과 금지 claim을 기록했다. 현재는 관계/업무 방식 등 제한된 해석까지만 지원하며 실제 확률·사건 날짜·인구 백분위는 제공하지 않는다. 독립 wealth 상세·hero 전체·today/month의 새 4역할 이관·선택형 타이밍 상세와 전문가/실증 검증은 별도 검토다.
