# 사주 런타임 검증

프로젝트 루트에서 사용한다. “런타임 검증해줘”, “사주 결과와 추가 질문 검증해줘”를 이 워크플로로 처리한다. 스킬을 사용한다고 먼저 알린다.

## 검토 계약

- [실행 절차](references/workflow.md)를 읽고 실제 본문·접힌 근거·표시된 질문·그 질문의 실제 답을 같은 회차로 동결한다. 저장된 옛 원고를 최신 런타임 결과로 부르지 않는다.
- 내용 기준은 [060의 C01~C06](../../../docs/planning/060-reading-method-requirements.md)을 유지한다. 평가의 단일 기준은 [runtime_reading_rubric.json](../../../apps/api/app/tools/data/runtime_reading_rubric.json)이다. job에 해당 기준과 버전/hash가 공급된다.
- **쉬운 문구와 말 흐름, 궁금증 충족, 추가 질문 흥미/유도, 질문이 약속한 실제 답**을 필수로 평가한다. 읽기 쉬운 일반론이나 이해하기 쉬운 한계 안내를 궁금증 해결로 승인하지 않는다.
- 명리 판단의 근거·적용 조건·반대 단서를 확인한다. 여러 관법의 이름/개수, 전문용어 삭제, 문단 길이가 통과 근거는 아니다. 핵심 답을 숨겨 클릭을 유도하거나 없는 특징·미지원 예측을 약속하면 실패다.
- 독자와 근거 검토를 별도 에이전트의 독립 job으로 실행한다. 작성자 자기 평가, 다른 역할의 판정, 예상 판정 예시, 통과 유도 지시를 공급하지 않는다. 해당 역할 job 전체를 계약 metadata까지 편집 없이 전달한다. 큰 job은 최초 자료 공급에 한해 지정한 자기 역할 job 파일 하나를 읽게 할 수 있다. 전체/hash 확인 후 검토 중에는 다른 파일/브라우저/도구/에이전트를 호출하지 않는다. 도구 접근을 기술적으로 차단하지 않았다면 `input_blind_only`로 보고한다. 이 위임은 사용자가 요청한 런타임 검증 범위에 한정한다.
- 검토 결과에는 실제 인용, 이해한 결론, 질문 충족 정도, 눌러 보고 싶은 **실제 메뉴 질문**과 새로 알 기대 내용, 문제의 수정 위치를 남긴다. 누락·오래된 hash·허구 인용은 evaluator가 거부한다.

## 실행과 완료

기본은 별도 프로세스의 fallback ASGI 캡처와 현재 대화의 검토 에이전트다. 생성 provider를 유료 모델로 바꾸거나 앱의 실행 설정을 변경하지 않는다. 사용자가 이미 저장한 실제 모델 결과를 검토할 수 있으나 원래 생성 provider와 캡처 시각·표시 범위를 명시한다. 새 모델 호출은 기존 프로젝트의 명시적 평가 권한/예산을 따른다.

런타임/브라우저 요청이면 현재 UI의 본문·기본 접힘·질문 선택·실제 답·복귀까지 확인한다. API 동결 자료와 실제 화면이 같은 문구/버전인지 대조한다. 브라우저 접근이 안 되면 API/내용 검토는 진행하고 UI를 HOLD로 남긴다. ASGI 검사를 브라우저 통과로 보고하지 않는다.

검토만 요청했다면 제품 문구·판정 규칙을 자동 수정하지 않는다. 수정까지 요청했으면 계산/규칙/결론 선택/문장/질문 중 실패 원인을 고치고 새 snapshot/job으로 최대2회 재검토한다. 원본 실패와 수정 이력을 보존한다. 근거 없는 새 예측을 추가해 통과시키지 않는다.

기계 오류·사실 실패·누락/보류·내용 실패를 분리한다. fixture와 미실행 검토는 HOLD다. FAIL을 평균 점수나 다른 역할의 PASS로 상쇄하지 않는다. 코드 PASS와 콘텐츠 PASS, 실제 사용자 흥미와 대리 에이전트의 클릭 의향을 구별한다.

최종 보고는 **쉬운가 / 궁금증을 채우는가 / 추가 질문을 누를 이유가 있는가 / 눌러서 약속한 답을 얻는가**, 각 판정의 인용과 남은 문제, 계산/내용/UI 범위를 짧게 제시한다. `docs/PROJECT_STATUS.md`, `docs/ai/WORK_LOG.md`와 산출물 ledger를 동기화한다. PASS는 전문가·예측 정확도·실사용자 만족의 인증이 아니다.
